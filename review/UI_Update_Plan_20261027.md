용도: Codex 구현 참고 및 중간보고용 개발 계획

## 1. 기획 목적

사용자가 직접 그린 네 장의 화면을 기준으로 비전투·전투·일시정지 메뉴의 인터페이스를 구분한다. 비전투 구역에서는 캐릭터 일러스트와 대화 내용을 크게 보여주고, 전투 구역에서는 플레이 공간을 확보하면서 캐릭터 주변에 상태와 대사를 표시한다. 화면 밖 NPC의 발언도 확인할 수 있게 한다.

이 문서는 업데이트 요구사항이다. 구현 완료나 검사 통과를 의미하지 않는다. 이번 작업에서는 현재 저장소를 다시 확인하지 않았으므로 아래 구현 파일 구성은 제안이다.

요구사항의 표기는 다음과 같다.

| 표기 | 의미 |
|---|---|
| 원안 | 사용자 그림 또는 손글씨 메모에서 확인한 내용 |
| 권장 | 원안을 실제로 사용하기 위해 추가로 제안하는 동작 |
| 미정 | 그림만으로 확정할 수 없어 구현 전에 정할 항목 |

생성한 완성형 UI 이미지는 외형 참고 자료이다. 원본 그림과 충돌하면 원본 그림과 사용자의 후속 지시를 우선한다. 생성 이미지에 추가된 설정·타이틀 버튼, 장식, 예시 수치 등을 확정 요구사항으로 취급하지 않는다.

## 2. 화면별 공통 원칙

### 원안

- 비전투 구역과 전투 구역의 UI를 다르게 구성한다.
- 비전투 구역에서는 대화용 일러스트와 하단 대화창을 사용한다.
- 전투 구역에서는 NPC 대사를 말풍선으로 표시한다.
- 플레이어가 입력한 채팅도 캐릭터 위에 표시한다.
- 화면 밖 NPC의 대사도 화면 안에서 확인할 수 있게 한다.
- ESC 키로 별도 메뉴를 연다.

### 권장 구현 기준

- 기준 작업 화면은 우선 1280×800으로 사용한다. 최종 해상도·배율은 별도로 확정한다.
- 장식 이미지와 실제 텍스트·버튼·입력창·체력 막대를 분리한다.
- 화면 크기가 바뀌어도 입력창·말풍선·메뉴가 화면 밖으로 잘리지 않도록 한다.
- 체력·탄약·임무 상태는 실제 게임 값을 읽어서 표시한다.
- 대사 생성, 화면 표시, 지원 행동 실행을 구분한다. 대사에 치료 완료라는 말이 나왔다는 이유로 체력을 변경하지 않는다.
- 현재 사용 중인 한글 조합·전송 처리는 재사용하고 새 UI에서 회귀 확인한다.
- 최종 색상·글꼴·테두리·장식은 미정이다. 이전에 생성한 SF 시안의 색상은 참고안이다.

## 3. 비전투 구역 인터페이스

### 원안 상세

| ID | 요소 | 배치·기능 |
|---|---|---|
| NC-01 | 캐릭터 표현 | 비전투 구역에서 캐릭터를 크게 볼 수 있도록 구성 |
| NC-02 | NPC 대화 표시 | NPC 머리 위에 말풍선 또는 대화 가능 표시를 배치 |
| NC-03 | 대화창 | 화면 하단을 가로지르는 넓은 대화창 |
| NC-04 | 캐릭터 일러스트 | 대화창 왼쪽에 배치하고 대화창 위로 일부 돌출 |
| NC-05 | NPC 대사 | 일러스트 오른쪽의 넓은 영역에 표시 |
| NC-06 | 답변 입력창 | 대화창 하단에 플레이어가 직접 입력할 영역 |
| NC-07 | 클릭·Space 조작 | 그림에 왼쪽 클릭·스페이스바 조작이 기재되어 있음. 정확한 기능은 미정 |

그림의 대사 예시는 정전과 퓨즈 필요성을 안내하는 내용이다. 실제 대사는 현재 임무 상태와 연동한다.

### 권장 동작

- 화자 이름과 일러스트를 연결한다.
- 대사 표시 영역과 질문 입력 영역을 분리한다.
- 입력 포커스가 있을 때 Space는 띄어쓰기로 처리한다.
- 클릭으로 대사를 넘기는 기능을 채택하면 대사 영역에서만 동작하게 한다.
- 전송 후 응답 대기·정상 응답·오류 상태를 구분한다.
- 일러스트 원본 비율을 유지하고, 입력창이나 대사를 가리지 않게 한다.
- 캐릭터를 크게 보이게 하는 연출은 카메라 줌으로 우선 검토한다. 이동 속도·충돌 크기를 함께 바꾸는 기능으로 간주하지 않는다.

### 미정

- 대화창을 항상 표시할지, NPC와 대화할 때만 열지.
- 대화 중 이동·사격·상호작용 및 게임 시간 진행 여부.
- 클릭·Space가 대화 시작, 다음 대사, 타이핑 효과 완료 중 무엇을 담당할지.
- NPC 머리 위 말풍선이 대화 가능 표시인지 실제 대사인지.
- 대사 표시 속도, 자동 진행, 대화 기록 제공 여부.
- 캐릭터·일러스트·대화창의 최종 크기.

### 완료 확인

- 일러스트·대사·입력창이 원안 배치대로 구분된다.
- 긴 대사와 긴 입력에서도 요소가 겹치지 않는다.
- 한글 마지막 조합 글자를 포함해 정상 전송된다.
- 입력 중 클릭·Space로 의도하지 않은 대사 진행이나 사격이 발생하지 않는다.

## 4. 전투 구역 인터페이스

### 원안 상세

| ID | 요소 | 배치·기능 |
|---|---|---|
| CB-01 | 전투 화면 | 비전투 구역보다 캐릭터를 작게 보이게 해 주변 전투 공간 확보 |
| CB-02 | 플레이어 체력 | 플레이어 캐릭터 아래 체력 막대 |
| CB-03 | 플레이어 무기 | 체력 표시 아래에 현재 무기 이미지 |
| CB-04 | 플레이어 탄약 | 무기 이미지 옆에 남은 탄창·탄약 수 표시 |
| CB-05 | NPC 체력 | NPC 캐릭터 아래 체력 막대 |
| CB-06 | NPC 무기·탄약 | NPC의 무기 이미지와 남은 탄창·탄약 수 표시 |
| CB-07 | 적 체력 | 적마다 각 캐릭터 아래에 체력 막대 |
| CB-08 | NPC 대사 | 전투 구역에서는 큰 비전투 대화창 대신 말풍선으로 표시 |
| CB-09 | 채팅 입력 | 화면 하단에 Enter를 눌러 사용하는 채팅 입력 영역 |
| CB-10 | 반투명 처리 | 채팅 후 반투명하게 표시한다는 메모. 적용 대상·시간·투명도는 미정 |

그림 속 무기 아이콘과 숫자는 표시 예시이다. 특정 총기·탄창 크기·장전 기능을 확정한 것은 아니다.

### 권장 동작

- 캐릭터 아래 HUD는 캐릭터 이동을 따라가되 글자 크기를 읽기 쉽게 유지한다.
- UI가 겹치면 플레이어 정보와 현재 중요한 대사가 우선 보이도록 한다.
- 적 체력은 원안대로 아래에 두되 발밑 HUD와 말풍선이 겹치는지 실제 전투에서 확인한다.
- 전투 말풍선은 짧게 표시한다. 긴 답변의 줄 수·전체 보기 방식은 별도로 정한다.
- 플레이어가 입력·마우스 조작을 다시 시작하면 채팅창을 읽을 수 있는 상태로 복원하는 방안을 검토한다.
- AI의 응답 대기와 실제 지원 중 상태를 혼동하지 않게 한다.

### 기능 의존성

- NPC 무기·탄약을 실제로 표시하려면 NPC의 무기·사격·탄약 데이터가 필요하다. UI를 그리는 작업과 NPC 전투 기능 구현을 구분한다.
- NPC 체력 표시에는 실제 체력·피해 정책이 필요하다. 무적 NPC에 임의로 감소하는 체력 막대를 넣지 않는다.
- 기존에 총 탄약만 관리했다면 탄창·예비 탄약을 구분하려면 장전 규칙도 추가로 정의해야 한다.
- 지원 잔량으로 대체하는 방안은 이전 답변의 제안이며 원안 변경 승인이 아니다.

### 미정

- 탄약 표시를 현재 탄창/예비 탄약으로 할지, 보유/최대치로 할지.
- NPC의 사격·피격 기능을 이번 업데이트에 포함할지.
- 전투 채팅 입력 중 이동·사격·게임 시간 진행 여부.
- 채팅 후 반투명해지는 대상이 입력창인지, 대사인지, 둘 다인지.
- 반투명 전환 시점·지속 시간·불투명도.
- 적 체력을 항상 표시할지, 근접·피격 시에만 표시할지.
- 말풍선 유지 시간·최대 줄 수·연속 발언 처리.

### 완료 확인

- 플레이어·NPC·적의 표시가 각 대상을 따라간다.
- 모든 수치가 실제 데이터와 일치한다.
- 여러 대상이 모여도 중요한 정보가 가려지지 않는다.
- Enter로 입력하고 전송 후 정해진 조작 상태로 돌아온다.
- 채팅창의 투명도가 바뀌어도 다시 입력할 수 있다.

## 5. 미니맵

### 원안 상세

| ID | 요소 | 배치·기능 |
|---|---|---|
| MM-01 | 위치 | 전투 화면 왼쪽 위 |
| MM-02 | 탐색 표시 | 지나온 구역을 밝게 표시 |

### 권장 동작

- 탐색한 영역과 미탐색 영역을 시각적으로 구분한다.
- 플레이어 현재 위치를 표시한다.
- 게임 화면과 같은 구역 정보를 기반으로 맵을 그린다.
- 탐색 기록과 현재 원형 시야 효과는 구분한다. 지나온 곳을 밝히는 기능은 영역을 기억해야 한다.

### 미정

- 미니맵이 현재 방만 보여줄지, 여러 방·전체 지도를 보여줄지.
- 현재 보이는 곳과 과거에 탐색한 곳을 다르게 표시할지.
- NPC·적·문·목표 아이콘을 표시할지.
- 재시작·구역 이동·저장/불러오기 시 탐색 기록을 유지할지.
- 전체 맵 보기나 확대 기능을 제공할지.

### 완료 확인

- 이동에 따라 탐색한 구역이 표시된다.
- 정해진 초기화·저장 정책에 따라 탐색 기록이 유지되거나 초기화된다.
- 미니맵이 채팅·말풍선·주요 HUD를 가리지 않는다.

## 6. 화면 안·밖의 채팅 표시

### 원안 상세

| ID | 요소 | 배치·기능 |
|---|---|---|
| SP-01 | 플레이어 채팅 | 플레이어가 입력한 말을 자기 캐릭터 위 말풍선에 표시 |
| SP-02 | 화면 밖 NPC 대사 | NPC가 화면 밖에 있어도 화면 가장자리에서 대사를 확인 |
| SP-03 | 위치 표현 | 원안에는 오른쪽 아래의 가장자리 대화 예시가 있음 |

오른쪽 아래 예시는 위치 표현의 사례다. 모든 화면 밖 NPC 대사를 항상 오른쪽 아래에 고정한다는 규칙은 원안에서 확정되지 않았다.

### 권장 동작

- 화면 안 NPC는 머리 위 말풍선, 화면 밖 NPC는 가장자리 표시를 사용한다.
- 화면 밖 표시는 NPC 이름 또는 작은 초상화로 화자를 식별한다.
- NPC가 있는 방향을 함께 표시한다.
- 가장자리에서 여백을 확보하고 말풍선 전체가 화면 안에 들어오게 한다.
- NPC가 화면 안팎으로 이동하면 표시 방식을 전환한다. 같은 대사를 두 곳에 동시에 중복 표시하지 않는다.
- 플레이어 말풍선은 전송된 문자열을 사용하며 미전송 초안을 노출하지 않는다.

### 미정

- 가장자리 표시를 NPC 방향에 따라 이동할지, 고정된 통신 영역을 사용할지.
- 이름·초상화·방향 표시의 포함 여부와 외형.
- 긴 대사의 길이 제한·표시 시간·기록 방식.
- 플레이어와 NPC의 동시 발언·연속 발언을 어떻게 배치할지.
- 장애물 뒤에 있지만 화면 안인 NPC도 가장자리 대사로 처리할지.

### 완료 확인

- 전송한 플레이어 대사가 캐릭터 위에 표시된다.
- 화면 밖 NPC의 발언을 화면 안에서 확인할 수 있다.
- 카메라 이동·줌 변경 후에도 말풍선 위치가 맞는다.
- 화면 경계에서 대사가 잘리지 않고 HUD를 가리지 않는다.

## 7. ESC 메뉴

### 원안 상세

| ID | 요소 | 배치·기능 |
|---|---|---|
| ES-01 | 메뉴 열기 | ESC 키를 누르면 메뉴 표시 |
| ES-02 | 메뉴 외형 | 모서리가 꺾인 기계 장치 형태의 창 |
| ES-03 | 톱니바퀴 | 창 왼쪽 위에 돌출 배치 |
| ES-04 | 톱니바퀴 반응 | 마우스를 올리면 한 바퀴 회전 |
| ES-05 | 저장 버튼 | 현재 진행 상태 저장 |
| ES-06 | 불러오기 버튼 | 세이브 목록에서 선택 |
| ES-07 | 예비 버튼 | 기능 없는 큰 버튼 두 개를 배치 |
| ES-08 | 장식 캐릭터 | 창 오른쪽에서 캐릭터가 귀엽게 빼꼼 보이는 연출 |
| ES-09 | 세로 장식 | 창 안 오른쪽 위의 세로 영역. 기능은 기재되지 않음 |

예비 버튼을 설정·타이틀 이동 기능으로 확정하지 않는다. 세로 장식 역시 진행도·음량 막대 등으로 임의 해석하지 않는다. 톱니바퀴의 회전은 원안 요구이며 톱니바퀴 클릭 기능은 미정이다.

### 권장 동작

- 메뉴가 열려 있을 때 월드 클릭·사격 입력을 차단한다.
- 톱니바퀴는 마우스 진입에 한 번 반응하고 중복 회전이 누적되지 않게 한다.
- 예비 버튼은 눌러도 게임 상태를 변경하지 않게 한다.
- 불러오기는 저장 목록을 연 뒤 선택 항목을 복원하는 흐름으로 설계한다.
- 저장·불러오기의 성공·실패를 짧은 문구로 알린다.
- ESC 입력을 대화창과 메뉴가 동시에 처리하지 않도록 우선순위를 정한다.

### 저장 데이터 후보 — 권장, 확정 아님

- 현재 구역·플레이어 위치
- 퓨즈 획득·전력 복구 등 임무 상태
- 플레이어 체력·탄약·지원 재고
- 적 생존·체력·위치
- 이미 사용한 탄약함 등 상호작용 상태
- 미니맵 탐색 기록을 유지하기로 한 경우 해당 기록

대화 기억·표시 기록·NPC 위치·진행 중인 지원·재사용 대기시간을 저장할지는 별도 결정한다. 실행 중인 HTTP 요청 자체는 저장 데이터로 취급하지 않는다. 불러오기 이전 요청이 나중에 도착해 새 상태에 적용되지 않도록 처리한다.

### 미정

- ESC 메뉴가 게임을 완전히 일시정지할지.
- 메뉴를 닫는 방법: ESC 재입력, 닫기 버튼, 배경 클릭 등.
- 저장 슬롯 개수·표시 정보·덮어쓰기·자동 저장 여부.
- 전투 중 저장 가능 여부.
- 사망·임무 완료 상태의 저장 정책.
- 메뉴를 여는 동안 한글 입력·미전송 초안을 유지할지.
- 톱니바퀴 회전 시간과 반복 조건.
- 장식 캐릭터를 정지 이미지로 할지 짧은 애니메이션으로 할지.

### 완료 확인

- ESC로 메뉴가 열리고 정해진 방식으로 닫힌다.
- 마우스를 올리면 톱니바퀴가 정확히 한 바퀴 돈다.
- 저장 후 값을 변경하고 불러왔을 때 저장 상태로 복원된다.
- 저장 파일이 없을 때도 정상적으로 안내한다.
- 예비 버튼 두 개는 실제 기능을 실행하지 않는다.

## 8. 화면 전환·키 입력 결정표

다음은 구현 전에 확정할 제안 표다. 원안에 없는 조작을 이미 승인된 요구로 해석하지 않는다.

| 입력·상황 | 권장 처리 | 상태 |
|---|---|---|
| 비전투에서 NPC 상호작용 | 비전투 대화창 열기 | 권장 |
| 전투에서 Enter | 채팅 입력 활성화 | 원안 |
| 입력 중 Enter | 질문 전송 | 권장 |
| 입력 중 Space | 띄어쓰기 | 권장 |
| 읽기 상태에서 클릭·Space | 대사 진행 기능 채택 시 다음 대사 | 미정 |
| 입력 중 Esc | 한글 조합·입력 종료를 먼저 처리 | 권장 |
| 입력하지 않을 때 Esc | 메뉴 열기 | 원안 |
| 메뉴에서 Esc | 메뉴 닫기 | 권장 |
| 구역 전환 | 해당 구역 UI로 전환, 입력 상태·초안 보존 정책 적용 | 권장, 세부 미정 |
| 저장 불러오기·재시작 | 이전 회차/상태의 응답 적용 방지 | 권장 |
| 전투 입력 중 시간 진행 | 계속 진행/전체 정지 중 선택 | 미정 |

원형 시야·캐릭터 카메라 줌·UI 모드는 별개로 관리한다. 연구 실험에 사용할 때는 모든 비교 방식에 같은 입력·시간 진행 정책을 적용한다.

## 10. 구현 제안

### 권장 파일 구성

아래 경로는 새로 만들 파일을 포함한 제안이다. 기존 main.gd의 참조·신호·입력 처리를 확인한 후 적용한다.

| 파일 | 역할 |
|---|---|
| game/scenes/ui/DialoguePanel.tscn | 비전투 대화 UI |
| game/scenes/ui/CombatHUD.tscn | 미니맵·전투 채팅 UI |
| game/scenes/ui/ActorStatus.tscn | 대상별 체력·무기·탄약 표시 |

| game/scenes/ui/PauseMenu.tscn | ESC 메뉴 |
| game/main.tscn, game/main.gd | UI 배치·신호 연결·입력 우선순위·화면 전환 |
| 대상 캐릭터·카메라 관련 씬/코드 | 위치 추적·구역별 카메라 설정 |
| 저장 담당 코드 | 저장 데이터·슬롯·복원. 별도 설계 후 추가 |

### 적용 순서 — 권장

1. 비전투 대화창의 정적 배치를 만들고 실제 한글 입력·응답 표시를 연결한다.
2. 비전투/전투 UI 전환과 카메라 줌을 확인한다.
3. 캐릭터 아래 상태와 일반 말풍선을 연결한다.
4. 화면 밖 대화 표시·전투 채팅·반투명 처리를 추가한다.
5. ESC 메뉴 외형·입력 차단·회전 효과를 적용한다.
6. 미니맵 탐색 기록·저장 목록·상태 복원을 구현한다.
7. 실제 해상도와 전투·입력·구역 이동·불러오기 상황을 점검한다.

이 순서는 작업 제안이다. 원안 기능을 삭제하거나 생략하도록 승인한 것은 아니다.

## 11. Codex 전달용 지시

네 장의 원본 스케치와 이 문서를 함께 제공한다.

> 이 문서는 게임 UI 업데이트 요구사항이다. '원안'은 사용자 그림에서 확인한 요구, '권장'은 구현 제안, '미정'은 아직 확정하지 않은 항목이다. 우선 현재 프로젝트의 관련 씬·참조·입력 처리만 확인하고, 비전투 대화창부터 적용할 수정 파일과 최소 코드 또는 편집기 작업을 제시하라. 전체 프로젝트를 재작성하지 말고 관련 파일만 다룬다. 한글 입력·AI 연결·실제 상태 표시를 재사용한다. 생성 시안은 외형 참고로만 사용하고 원본 스케치의 기능 없는 버튼을 임의의 기능으로 바꾸지 않는다. NPC 무기·탄약·체력, 미니맵 탐색, 저장은 실제 기능 데이터가 필요한 작업으로 구분한다. 미정 동작은 임의 확정하지 말고 해당 작업에 필요한 항목만 모아 확인한다.
