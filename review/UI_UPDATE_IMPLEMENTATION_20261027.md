# UI 업데이트 구현 기록 — 2026-10-27

첨부 `UI_Update_Plan_20261027.md`의 기능을 기존 Godot 프로젝트에 연결했다. 사용자 후속 답변에 따라 하린의 사격·피격도 포함했다. 작업 시작 전 수정된 소스는 `ui_plan_before_20261027.zip`에 보존했다. 기존 한글 TextEdit, 네이티브 IME DLL, AI 클라이언트와 세 제공자의 공통 지원 실행 경로를 재사용했다.

네 장의 원본 스케치 파일 자체는 이번 입력에 첨부되지 않았다. 문서의 ChatGPT Library 링크에서는 원본을 가져오지 못했으므로, 문서의 상세 배치·기능과 이미 로컬에 있는 초상화/스타일을 기준으로 구현했다. 원본과 픽셀 단위로 동일한 외형이라는 의미는 아니다.

## 채택한 동작 정책

사용자에게 정책 묶음을 제시한 뒤 받은 “NPC 사격·피격도 이번에 포함” 답변을 반영해 나머지 제안 기준으로 진행했다.

- 비전투 대화창은 기존대로 시작 시 열고 닫기/재열기와 초안을 유지한다. 구역별 UI를 바꿔도 같은 ChatInput을 사용한다.
- 질문 입력·대화·F3 설정 중 전투 시간은 진행한다. ESC 메뉴만 월드 전체를 멈춘다.
- 한글 조합 중 Esc는 조합 취소, 입력 중 Esc는 입력 종료, 입력하지 않을 때 Esc는 메뉴 열기, 메뉴에서 Esc는 복귀다.
- Space/클릭은 기존 사격으로 유지한다. 입력창·메뉴·말풍선·미니맵 등 UI 클릭은 월드 사격을 가로챈다.
- 화면 밖 대사는 NPC 방향 가장자리에 둔다. 목표·미니맵·다른 HUD와 겹치면 가까운 빈 위치로 옮긴다. 화면 안에서는 연결선으로 화자를 표시한다.
- 탐색은 방별로 회차 내 유지한다. 재시작은 초기화하고 저장에는 포함한다. 원형 시야와 탐색 기억은 별도다.
- 전투 중 저장 가능, 사망/임무 완료 상태 저장 제한. 슬롯 3개, 기존 슬롯은 같은 슬롯을 다시 선택해 덮어쓰기. 자동 저장은 없다.

## 하린의 실제 전투 규칙

모든 제공자가 동일한 규칙을 사용한다. 기본 체력 100, 탄약 20, 한 발 피해 25, 사격 간격 1초다. 하린 자신의 시야 반경 안에서 가장 가까운 적에게 실제 Projectile을 발사한다. 지원 행동을 수행하는 동안에는 사격하지 않는다. 드론은 플레이어와 살아 있는 하린 중 가까운 대상을 공격한다. 보호 장비 안에서는 하린도 같은 피해 감소를 적용받는다.

체력 0인 하린은 이동·사격·지원이 중단되고 지원 후보는 wait뿐이다. 플레이어는 혼자 임무를 계속할 수 있다. 재시작/이전 저장으로 회복하며 구역 왕복으로 회복하지 않는다. 자기 치료·자기 보급·탄창/장전은 추가하지 않았다. 수치는 World Inspector에서 조정한다. 전투 조건을 바꿨으므로 이전 실험 데이터와 합쳐 집계하지 않는다.

## 저장과 요청 취소

`user://mission_saves/slot_1.json`~`slot_3.json`을 사용한다. 현재 런처는 user://를 `runtime/appdata/Godot/app_userdata/로컬 AI NPC 연구 시제품/`에 둔다.

저장 범위는 구역, 플레이어/NPC 위치, 임무 플래그, 체력·양측 탄약·지원 재고, 적 체력·위치·공격 대기, 사용한 탄약함, 보호 장비 지속시간, 지원 재사용 대기, 방별 탐색, 최근 공유 사건과 AI 대화 기억 3개다. 제공자도 복원한다.

진행 중 지원·탄환·HTTP 요청·미전송 초안·일시적 UI 대화 기록은 복원하지 않는다. 진행 중 지원은 아직 자원을 소비하기 전 상태로 취소한다. 로드 시 HTTP 연결과 대기 질문을 취소하고 epoch를 증가시켜 과거 결과를 무효화한다. 실제 로컬 요청 중 불러오기 → 새 질문 → 새 답변까지 별도 검사했다.

로드는 파일 크기, JSON 구조, 형식 버전, 전투 규칙 해시, 값 범위·자료형·위치·적 목록·탐색 셀을 먼저 검사한다. 실패하면 현재 월드를 변경하지 않고 안내한다. 쓰기는 임시 파일→기존 슬롯 백업→교체 순서이며 실패 시 기존 슬롯을 보존한다. 중단된 교체의 백업도 읽을 수 있다.
