# 게임 구성과 논문 범위 — 2026-10-25

## 확정한 방향

사용자 요청을 반영한 핵심은 짧은 플레이 안에서 로컬 AI NPC의 적합성을 평가하는 것이다.
어두운 SF 픽셀아트를 지향하되 이번 구현은 게임 구조와 비교 가능한 NPC 행동을 우선했다. 목표 플레이 길이는 대화·탐색을 포함해 약 3–5분으로 잡고, 실제 사람 플레이 시간은 별도 측정한다.

연구실 → 원형 시야의 어두운 보관 구역 → 소규모 드론 전투 → 퓨즈 회수 → 연구실 복귀 → 전력 복구 → 임무 완료.

하린은 플레이어와 서로 믿는 친한 동료다. 함께 이동하며 임무 질문, 지원 질문, 관계/일상 질문에 응답한다.
이번 회차의 공유 사건과 최근 대화 최대 3쌍을 문맥으로 사용한다. 장기 기억 저장·연애·복잡한 관계 수치 시스템은 범위에 포함하지 않는다.

## 이번에 구현한 동작

- 두 구역 왕복. 연구실에서 퓨즈를 얻는 이전 구조를 제거하고 보관 구역의 전투 종료 뒤 회수하게 변경.
- 플레이어 중심의 원형 시야. 반경을 Inspector에서 조정.
- 드론 3기: 추적·접촉 피해·체력·탄환 적중·사망. 클릭 방향 사격과 시야 안 가까운 적을 조준하는 Space 입력.
- 체력, 제한된 탄약, 비상 탄약함, 사망/재시작.
- 하린의 접근 치료, 탄약 보급, 보호 장비 설치, 실제 보호 위치를 기준으로 한 방향 호출.
- 보호 장비 안의 기본 피해 50% 감소. 설치와 위치 안내는 별도 행동.
- 실시간 비동기 판단. 입력 중에는 플레이어 이동만 제한하고 전투는 지속.
- 반환 시 맵/회차/사망 상태, 판단 유효 시간과 현재 자원을 다시 검사. 오래된 결과로 지원 자원을 소비하지 않음.
- 세 방식 선택과 회차 초기화. 공통 행동 실행과 상태·결과 기록.
- 주요 설정·위치·그림은 저장된 Godot 씬과 Resource에서 편집.

## 비교 시스템 정의

| 항목 | 규칙 기반 | 로컬 LLM | Jev |
|---|---|---|---|
| 행동 선택 | 명시한 우선순위 규칙 | 같은 상태와 후보에서 JSON 행동 선택 | 공식 Choice 질문으로 후보 선택 |
| 행동 실행 | 공통 실행기 | 공통 실행기 | 공통 실행기 |
| 임무/일상 질문 | 키워드 의도 + 고정 문장 | 상태·관계·최근 사건을 바탕으로 대사 생성 | 질문 의도 선택 + 고정 문장 |
| 외부 네트워크 | 사용하지 않음 | localhost Ollama | TypeSafe 공식 API |
| 현재 실호출 검증 | 해당 없음 | 확인 | 미확인, 호출 0회 |

Jev는 공식 문서에서 상태와 typed 질문으로 구조화된 결정을 반환하는 모델로 설명한다.
자유 대사 생성 자체를 세 모델의 동등한 능력으로 비교하지 않는다. Jev에 로컬 LLM을 붙이면 **Jev+LLM 혼합 시스템**이라는 별도 조건이다.
현재 구현에는 자동 혼합이나 다른 방식으로의 숨은 대체가 없다.

모든 방식은 같은 행동 후보와 실행 조건을 사용한다. 하린의 기본 추적은 공통 낮은 수준의 동작이며, 매 프레임 경로 이동을 모델이 생성하지 않는다.
체력/탄약 등 긴급 지원 우선과 예방적 보호라는 과제 지침은 공통이다. 규칙 기반의 숫자 임계값은 정책 소스에 공개한다.

## 현재 선택과 개발 관찰

- 엔진: Godot 4.7.2 / GDScript.
- 로컬 추론: Ollama 0.40.11 / Qwen3 4B, 명시적 think=false와 JSON 스키마.
- 모델은 이미 설치된 것을 사용했으며 새 대용량 다운로드를 하지 않았다.
- Qwen2.5 1.5B는 개발용 기본 사례에서 체력/탄약 부족을 보고도 보호 장비를 우선 선택한 경우가 있었다.
- Qwen3 4B는 비구조화 대사에서 생각 과정이 본문으로 섞이고 길이 제한에 걸린 사례가 있었다. 구조화된 dialogue 필드를 사용한 뒤 대사 반환을 확인했다.
- 최종 프롬프트 버전은 companion_v1.4. 개발용 행동 3건에서 치료 / 보급 / 보호 설치를 반환했다. 더 넓은 상황의 행동 적절성은 미평가.
- 임무 경로 안내는 확인했다. 관계 대화에 다른 언어의 조각이 섞이거나, 일상 질문에서 임무 안내로 되돌아오는 사례가 남아 있다.
- 초기 출력에는 제공되지 않은 과거를 만들어 낸 사례도 있었다. 실패와 원문은 보존하며 자연스러움·사실 일관성을 완료 처리하지 않는다.
- Jev 기본 모델 식별자는 설정 가능한 jev-1.13.0이다. 실제 계정에서 사용 가능한 모델명과 응답 모델 확인이 필요하다.

이 기록은 프롬프트와 모델을 정한 개발 과정이다. 본 실험 결과로 합산하지 않는다.
형식이 유효하고 실행이 수락되었다는 사실은 행동이 적절하거나 문장이 자연스럽다는 뜻이 아니다.

## 검증 완료

- 임무·전투·지원·씬 저장·재로드 등 기능 검사 50/50.
- 규칙 기반 렌더링 자동 흐름: 출발 → 전투 → 퓨즈 → 복귀 → 전력 → 완료.
- 실제 로컬 LLM 통합 5/5: 치료 적용, 탄약 적용, 추론 중 이동, 맵 전환 뒤 이전 응답 폐기, 임무 경로 대사.
- 위 로컬 통합은 headless와 실제 그래픽 렌더링 실행에서 모두 확인.
- Jev 합성 응답 파서와 키 없는 오류 처리. 실제 Jev 인증·추론·응답 속도는 미확인.
- 사람에 의한 전체 플레이, 다른 PC, 배포용 실행 파일, 네트워크 단절, 장시간 반복 비교는 미검증.

기존 테스트 파일을 보존하고 새 검사를 game/tests에 추가했다. 기존 테스트를 새 명세로 덮어쓰는 작업은 자동 승인 검토가 검사 범위 손실 위험으로 거부하여 진행하지 않았다.

## 논문의 연구 질문

1. 로컬 LLM이 짧은 실시간 전투에서 게임 진행을 멈추지 않고 필요한 지원을 선택할 수 있는가?
2. 같은 과제에서 규칙 기반·로컬 LLM·Jev의 지연, 유효/적절 행동, 실패·오래된 응답, 실제 지원 결과는 어떻게 다른가?
3. 로컬 생성 대화가 임무 정확성·동료 관계의 일관성·일상 대화 자연스러움에서 고정 문장 방식과 어떤 차이를 보이는가?
4. 로컬 실행에 필요한 CPU/GPU·메모리와 온라인 API의 의존성·실패/비용은 이 규모의 게임에서 어떤 제약인가?

논문 주장은 이 시나리오·모델·장비·설정 안의 결과로 제한한다. 모든 NPC, 모든 로컬 모델 또는 모든 하드웨어에 일반화하지 않는다.

## 다음 작업 순서

1. 사용자가 현재 구조를 직접 플레이하며 이동 속도, 탄약, 적 피해와 시야 반경을 확인.
2. Jev 실행 환경의 키 준비 후 작은 범위에서 실제 인증·선택·오류 동작 확인. 키를 채팅·프로젝트 리소스에 저장하지 않음.
3. 로컬 대사에서 관계/일상 품질과 상태 사실성 보완. 개발 사례와 본 평가 질문 분리.
4. 시나리오와 설정을 고정한 뒤 비교 데이터 수집. 자세한 초안은 EXPERIMENT_PROTOCOL.md.
5. 두 구역의 통일된 픽셀아트·기본 애니메이션·음향 적용. 공통 전투 조건을 바꾸면 본 실험 데이터를 다시 수집.
6. 그림·표·실험 결과를 논문에 반영하고 실제 실행 방법과 한계 정리.
