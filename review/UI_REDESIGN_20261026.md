# SF 통신 UI 개편

현재 화면을 시험 도구처럼 보이게 하던 상단 설정·수치 나열을 체력/탄약 HUD, 단계별 임무 줄, 하린 통신 패널로 바꿨다. 먹색 배경에 청록을 기본으로 쓰고 목표·부족한 탄약은 호박색, 위험 체력·응답 오류는 붉은색과 문구로 함께 표현한다.

Canva 연결 플러그인으로 원본 픽셀 초상화를 생성해 `game/assets/ui/harin_canva.png`로 저장했다. 결과가 반환한 PNG는 200×200이며 통신창에서 100×100으로 표시한다. 출처·프롬프트는 `game/assets/ui/ASSET_SOURCE.md`에 있다. 이미지 생성에 필요한 프롬프트만 Canva에 전달했으며 논문·소스·게임 대화 기록을 업로드하지 않았다.

## 실제 반영

- 체력 변화에 0.18초 막대 전환, 위험 문구, 실제 탄약·남은 지원 장비.
- 방·전투·퓨즈·전력 복구에 연동한 4단계 임무 표시.
- 하린 초상화·역할·대사·입력창과 대기/입력/응답/오류 상태.
- 임무·지원·일상 질문 초안 버튼. 자동 전송하지 않으며 미전송 문장을 보존한다.
- F3 실험 설정: 방식 변경, 새 회차, 실제 요청 측정. 변경 시 같은 초기 조건으로 재시작한다.
- HUD 클릭의 사격 전파 차단. 질문/설정창의 이동 제어. 전투·AI 판단 주기는 계속된다.
- 기존 TextEdit/Windows IME 연결 모듈을 유지하며 전송 버튼은 입력 포커스를 빼앗지 않는다.
- 주요 UI는 저장된 Godot Control/Theme 리소스이므로 편집기에서 직접 수정할 수 있다.

## 검증 범위

UI 전용 35개, 임무 50개, 채팅 27개, 네이티브 입력 모듈 로드 6개, 네이티브 입력 연결 합성 11개 검사. 결과 JSON은 `evidence/ui_redesign/ui_layout_test.json` 및 기존 검증 디렉터리에 보존한다. 기본 `VERIFY_MISSION.cmd`에 UI 검사도 포함했다.

사용자가 요청한 화면 조작 금지를 유지했다. 이번 작업은 헤드리스 코드 검사와 씬 배치 검사만 했다. 실제 Microsoft IME, 실제 GPU 렌더링, 창 크기 변경의 육안 확인은 이번 결과가 보증하지 않는다. 기존 채팅 오류가 실제 입력기에서 해결되었다고 새로 주장하지 않는다.

`evidence/ui_redesign/ui_layout_preview.svg/png`는 실제 씬 트리에서 내보낸 사각형·문자·테마·에셋을 재구성한 **정적 배치 미리보기**다. 실제 게임 화면 캡처가 아니며 셰이더, 임의 그리기, 글꼴 조판과 스크롤바를 완전히 재현하지 않는다. 재생성은 헤드리스 UI 검사 후 `scripts/render_ui_layout_preview.cjs`를 사용한다. Node/Sharp는 Codex 번들 의존성 경로를 참조하므로 이 스크립트는 게임 실행에 필요하지 않다.

기존 UI 원본: `review/ui_before_20261026/`. 전투 수치, 임무 규칙, 비교 제공자, 원형 시야, 모델 프롬프트는 바꾸지 않았다. 모든 방식에 동일한 UI가 적용된다. 본 실험에서는 질문 입력 방식도 동일하게 사용해야 한다.

맵/이동 캐릭터의 최종 픽셀아트·애니메이션은 여전히 별도 작업이다. 이번 변경은 UI와 통신 초상화의 개편이다.
