# 정전된 연구소 — 어두운 SF 픽셀아트 방향

작성일: 2026-10-25
선택한 방향: 어둡고 분위기 있는 SF 픽셀아트.
범위: 연구소 한 구역, 플레이어 1명, 정비사 NPC 1명, 퓨즈·전력 장치·출구, 기존 상태 연동 대화.

## 시안의 상태

- `dark_sf_target_v1.png`는 내장 이미지 생성 도구로 만든 **목표 화면 참고 시안**이다.
- 실제 Godot 실행 화면이나 사용 가능한 타일셋/스프라이트 시트가 아니다.
- 현재 게임 코드·씬·그래픽은 이번 검토에서 변경하지 않았다.
- 시안의 세부 묘사를 그대로 재현하는 작업 시간은 추정하지 않았다. 아래 시간은 범위를 줄인 1차 그래픽 패스의 계획치다.
- 최종 생성 프롬프트: `generation_prompt.txt`. 기존 실제 화면은 `evidence/scene_refactor/03_after_power.png`.

## 현재 화면에서 먼저 고칠 것

1. 게임 화면을 넓힌다. 큰 우측 대화 패널과 개발용 제목·상태 검증 버튼이 시야를 차지한다. 대화는 하단 오버레이로, 성능 수치와 상태 조작은 개발 패널로 옮긴다.
2. 격자 바닥을 실제 벽·바닥·문·보관함이 있는 방으로 바꾼다. 큰 맵을 만들기보다 이동 가능한 중앙과 소품이 모인 벽면을 구분한다.
3. 하나의 기반 타일셋을 고른다. 시점·픽셀 밀도·외곽선·명암 방향을 맞춘다. 서로 다른 팩의 그림을 단순히 같은 크기로 확대해 섞지 않는다.
4. 캐릭터 두 명을 같은 규격으로 만들고 기본 대기/걷기를 넣는다.
5. 조명과 상태 피드백을 넣는다. 어두운 공간에서도 통로와 상호작용 물체는 구별되어야 한다.

## 아트 규칙

- 시점: 위에서 내려다보는 RPG 시점, 벽 앞면이 보이는 정도. 등각 시점으로 바꾸지 않는다.
- 공간: 작은 연구실 한 구역. 바닥 패널, 벽 파이프, 보관함, 콘솔, 전력 장치, 잠긴 문으로 구성.
- 색: 남색·회색 바탕, 청록색 콘솔, 소량의 주황색 비상등. 중요한 물체만 밝은 포인트를 준다.
- 규격: 기반 팩을 고른 뒤 확정. 16px 팩이라면 예를 들어 월드 320×200을 4배로 표시하고, 32px 팩이라면 640×400을 2배로 표시한다. 두 방식 모두 현재 1280×800 화면 비율과 맞는다.
- 픽셀 월드는 Nearest 필터와 정수 배율을 기본으로 검토한다. 한글 대화 UI는 별도 고해상도 레이어로 유지한다. 문장 읽기 편한 글꼴을 사용한다.
- 카메라 이동과 물체 좌표에서 픽셀 떨림·잘림을 확인한다. 과한 CRT·노이즈·블룸으로 가리지 않는다.
- 초상화는 선택 사항이다. 한 장을 넣더라도 실제 캐릭터와 복장·색을 맞춘다.

## Godot 적용 구조

현재 저장된 씬 구조를 유지하면서 아래 부분을 확장한다.

- `game/scenes/World.tscn`: Floor/Walls/Props 레이어, 장식 배치, 월드 조명. 바닥·벽은 TileMapLayer와 TileSet으로 편집할 수 있게 구성.
- `game/scenes/Player.tscn`, `NPC.tscn`: 기본 Sprite2D를 애니메이션 가능한 구조로 확장하고 캐릭터의 발 위치를 기준점으로 잡는다. 기존 이미지/색 Inspector 속성과 충돌 형태는 함께 조정해야 한다.
- `Fuse.tscn`, `Generator.tscn`, `Exit.tscn`: 그림·표시등·작은 작동 애니메이션을 기존 게임 상태에 연결.
- `game/main.tscn`: 플레이 공간 중심 배치, 하단 대화창과 질문 입력, 작은 목표 표시. 개발 수치와 테스트 버튼은 개발 패널에 모아 예를 들어 F3으로 토글.
- 조명은 CanvasModulate + PointLight2D + 필요한 물체의 LightOccluder2D를 검토. UI는 CanvasLayer 등으로 월드 조명과 분리.
- NPC 이름·위치·목표 문구·조명 세기·소품 배치를 사용자가 Godot에서 직접 수정할 수 있게 저장한다.
- 현재 AI 클라이언트와 진행 조건은 그래픽 작업과 분리해 유지한다. 실제 대화 응답은 임의의 장식 문장으로 바꾸지 않는다.

Godot 공식 자료:
- [TileSet / TileMapLayer](https://docs.godotengine.org/en/stable/tutorials/2d/using_tilesets.html)
- [2D 조명과 그림자](https://docs.godotengine.org/en/stable/tutorials/2d/2d_lights_and_shadows.html)

## 제한된 일정의 적용 순서

| 순서 | 작업 | 계획 시간 |
|---|---|---:|
| 1 | 기반 팩 확인, 한 장면 배치 시험, 전체 화면/하단 대화 UI 구성 | 2–3시간 |
| 2 | 벽·바닥·대표 소품, 통로와 상호작용 위치 구성 | 3–4시간 |
| 3 | 같은 규격의 캐릭터 두 명, 기본 대기/걷기 | 3–5시간 |
| 4 | 조명, 퓨즈 하이라이트, 전력·문 상태 피드백 | 2–3시간 |
| 5 | 실제 이동/대화/탈출 점검, 화면 크기와 글자 확인 | 2–3시간 |
| 합계 | 범위를 줄인 첫 그래픽 패스 | 12–18시간 |

위 시간은 구현 후 측정한 실적이 아니다. 에셋의 실제 구성, 이미지 추출·수정량에 따라 늘어날 수 있다.

10월 27일 중간보고 전에는 1–2단계로 화면 인상이 달라지는 한 장면을 우선 목표로 한다. 대기/걷기·음향·세부 연출은 이후에 보완한다. 새 맵·전투·복잡한 인벤토리 확장은 이번 그래픽 패스에 포함하지 않는다.

## 완료 판단

- 두 캐릭터와 소품의 픽셀 크기·시점이 일관적이다.
- 정전 상태에서도 길과 상호작용 대상이 보인다.
- 퓨즈 획득 → 전력 복구 → 문 열림이 외형 변화로 전달된다.
- 이동·벽/소품 충돌·E 상호작용·질문 입력·AI 응답·탈출·재시작이 동작한다.
- 개발 UI를 감춘 상태로 한 장면을 캡처하면 게임 공간이 중심에 보인다.
- Godot에서 소품 이동과 조명 수정 후 저장·재실행해도 변경이 유지된다.
