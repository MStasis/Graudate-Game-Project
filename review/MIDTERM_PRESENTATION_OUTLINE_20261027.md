## 발표 기준

사용자가 전달한 평가 항목 네 가지가 각각 드러나게 구성한다.

- 계획 대비 현재 진행 사항
- 진행 중 문제
- 문제 해결을 위한 노력 및 방안
- 향후 진행 계획

현재는 Godot 2D 테스트 장면과 실제 로컬 모델의 상태별 응답 3건, 게임 규칙 검사 7개, 실행 화면을 확보했다. 기존 3D 코드는 재사용하지 않았다. 초기 모델 문제와 교체 과정도 실제 기록으로 남겼다. 최신 결과를 PPT에 반영했으며 발표 전 사용자가 직접 실행과 설명을 확인해야 한다.

## 1장: 연구 목표와 원래 계획

화면은 연구 목표 한 문장과 간단한 흐름도로 구성한다.

`게임 상황 → 현재 상태와 NPC 설정 → 로컬 언어 모델 → NPC 대사`

원래 계획의 핵심은 3D 그래픽이 아니라 게임 상황을 반영하는 로컬 AI NPC다. 비교 실험은 응답 지연, 상태 반영, 자원 사용을 중심으로 진행한다는 목표를 짧게 제시한다.

## 2장: 계획 대비 현재 진행

다음 표를 발표 시점의 증거로 채운다. ‘완료율 70%’와 같은 근거 없는 비율보다 작동 여부와 남은 작업을 쓰는 편이 명확하다.

| 계획 항목 | 현재 확인된 상태 | 발표 전 채울 증거 |
|---|---|---|
| 게임 프로토타입 | 작은 2D 장면의 퓨즈·전력·탈출·재시작 구현 | 실제 화면과 규칙 검사 기록 |
| 로컬 모델 구축 | Qwen2.5 1.5B 실제 대사 생성 | 모델·옵션·응답·시간 JSONL 기록 |
| 게임 상태 반영 | 동일 질문을 3가지 상태에서 확인 | 퓨즈 획득 전·후와 전력 복구 후 화면 |
| 비동기·스트리밍 | HTTPClient 부분 응답 표시와 생성 중 프레임 처리 확인 | 사람의 입력 조작과 다양한 실패 조건은 추가 확인 |
| API 비교 실험 | 로컬 예비 시연만 실시, 클라우드 비교 미실시 | 비교 계획과 미완료 범위를 명시 |

짧은 녹화 장면이 있다면 10~20초를 이 장의 60초 안에 포함한다. 녹화는 녹화라고 표시하고, 미리 작성한 대사는 모델 생성 결과처럼 제시하지 않는다.

## 3장: 진행 중 문제와 원인

- 사용자가 설명한 문제: 3D 에셋 준비 부담과 남은 일정. 월·금의 작업 시간 부족.
- 현재 진행상 문제: 새 2D 프로젝트 제작과 로컬 AI 연동 검증이 필요함.
- 아직 관측되지 않은 기술 위험: 한국어 대사 품질, 응답 지연, 게임 실행 중 자원 경쟁. 실제 문제가 발생한 것처럼 단정하지 말고 검증 예정 항목으로 구분함.

원인을 말한 뒤 바로 어떤 작업이 지연되거나 위험해지는지 연결한다. 예를 들어 에셋 준비가 길어지면 AI 연동과 비교 실험에 쓸 시간이 줄어든다는 점을 설명한다.

## 4장: 해결을 위한 노력과 방안

슬라이드를 ‘이미 수행한 일’과 ‘다음 조치’로 나눈다.

이미 수행한 일에는 실제로 한 내용만 넣는다. 현재 확인 가능한 예시는 제출 계획서 재검토, 2D 전환과 최소 범위 정리, Godot 후보 조사, 요일별 가용 시간을 반영한 일정 재계산이다. 모델 시험을 추가로 했다면 그때 모델명·문제·바꾼 설정·관측 결과를 넣는다.

다음 조치에는 다음 내용을 제시한다.

- Godot 기반의 작은 탐색·대화 게임을 우선안으로 선택하고 맵 1개·NPC 1명·목표 1개로 제한.
- 로컬 모델 1개의 한국어 대화를 먼저 검증하고, 상태 전달과 비동기·스트리밍을 순서대로 연결.
- 아이템·목표 판정은 게임 규칙이 관리하고 모델은 대사를 생성하도록 분리.
- 정해진 질문과 상태로 로컬·클라우드를 비교하고 로그를 남김.

‘최적화했다’, ‘해결했다’, ‘빨라졌다’는 말은 실제 전후 측정이나 작동 증거가 있을 때만 사용한다.
