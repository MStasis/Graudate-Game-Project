# Fleet B동 미카 대화 검증

## 기준이 되는 게임 상태

- `FleetDemo.context()`는 기존 `Step`, 열린 캐비닛, 퓨즈 장착, 고정 대사의 재생 상태, 서사 사건, 적 차수와 레버 조건을 읽는다. `DemoWorld.game_state()`의 기존 `fleet_context` 필드로 전달한다. 저장 형식과 시나리오 호환 해시는 기존 값을 사용한다.
- 입구 무전 직후에는 함선 통신망 상태가 미확인이다. 미카 방 대사 뒤에는 통신 장애가 확인된다. 전력을 복구한 뒤에도 통신의 원인이나 복구 여부는 확인되지 않는다.
- 퓨즈를 찾으러 가기, 캐비닛에서 떨어진 퓨즈 발견, 플레이어 보유, 전기실 주 퓨즈함 장착을 구분한다. 복도 선원과 B동 전투 사실은 각 장면에 도달한 뒤 제공한다. 격벽 작동 계획은 브리핑 뒤, 즉시 조작 안내는 미카 신호와 양쪽 위치 조건이 충족된 뒤 제시한다.
- RuleBased와 Jev의 의도별 응답은 같은 Fleet 사실을 사용한다. LocalLLM은 Fleet 전용 프롬프트에서 한국어 반말을 생성한다. 상태와 충돌하는 답변은 같은 모델에 한 번 재생성을 요청하며, 실패와 원문은 로그에 남는다. 미카의 직접 사격과 공통 실행기가 완료한 치료·보급·보호를 구분한다.

## 실행과 증거

저장소의 `scripts/verify_mission.ps1`에 Fleet 대화 검사를 추가했다. `-LocalAI`는 준비된 로컬 모델로 실제 응답을 수집한다. 이 작업에서는 기존 저장과 로그를 보존하기 위해 `runtime/fleet_dialogue_20261114/` 아래의 복사본에서 실행했다.

- Fleet 대화 상태 10개에서 지정 질문 5개씩 검사했다. RuleBased 답변, 프롬프트 사실, 구버전 회귀, Jev 의도 응답 모의 처리, 오래된 답변 폐기를 포함해 최종 233개 검사를 통과했다. `signal/evidence/fleet_dialogue/test.json`
- Fleet 본편 입력 재생 62개가 통과했다. `evidence/fleet_demo/test.json`
- 기존 기본 회귀는 `regression/evidence/verify_mission_final.log`에 기록했다. 실모델 전체 표본의 원문, 요청 상태와 측정값은 `final/evidence/fleet_dialogue/`에 있다. 후속 통신·퓨즈 표본은 `evidence/comms_final_*.log`, `evidence/live_final_fuse_held.log`에 있다. 복도 전투 직후와 B동 레버의 표본은 각각 `targeted/evidence/`와 `signal/evidence/`에 있다.

실제 `qwen3:4b`의 10단계 표본은 모두 응답을 표시했고 호출 시간은 약 17~35초였다. 일부 발화는 통신 상태, 회수한 퓨즈의 조작, 레버 조건을 잘못 말해 후속 수정을 했다. 잘못된 레버 안내를 보강한 뒤 전투 중에는 B동 전투 종료와 미카 신호를 모두 언급하는 발화를 확인했다. 전력 복구 후 통신 질문의 표본은 재확인하지 않았다고 답했지만 첫 문장의 현재형과 표현은 다듬을 여지가 있다. 호출 시간에는 모델 추론과 큐 대기 시간이 들어 있다.

구버전 LocalAI의 실요청 저장 취소는 7/7 통과했다. 별도로 실행한 로컬 통합 검사는 4/5였다. 손전등을 받으라는 답변은 실제 경로인 왼쪽 통로를 언급했지만 기존 단어 검사에 걸렸다. 수정 전 HEAD 복사본에서도 동일한 항목이 실패했다. 기존 테스트 기준은 유지했다.

전체 `verify_mission.ps1 -LocalAI`는 Fleet 실모델 검사와 기존 엔딩 요청 취소 7/7을 통과한 뒤, 기존 서사 대화 테스트에서 모델 생성 길이 한도로 한 건이 실패해 종료 코드 1로 끝났다. 기존 서사 대화는 14/15였고 이후 검사는 통합 실행에서 건너뛰었다. 전체 로그는 `final/evidence/verify_mission_local.log`에 있다.

Jev 외부 API 호출과 사람 플레이는 이번 검증에 포함되지 않았다. 문구 검사와 모델의 실제 생성 성공 여부는 응답의 의미 및 말투 검토와 별개로 기록한다.
