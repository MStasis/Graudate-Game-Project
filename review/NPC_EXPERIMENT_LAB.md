# NPC 성능 비교 실험실

타이틀의 **NPC 실험실**에서 미카의 규칙 기반 응답과 로컬 Qwen3 응답을 같은 조건으로 비교할 수 있다. 각 요청은 본편과 같은 `World.tscn`과 `NPCBrain.tscn`을 사용한다. 실험실은 별도의 물리 월드와 기록 폴더를 소유한다.

## 실행과 논문 데이터 수집 순서

1. 저장소 루트에서 `START_LOCAL_AI.cmd`를 실행한다. 런처가 설정된 Ollama 서버와 모델 설치를 확인하고 게임을 연다.
2. **NPC 실험실 → 예비 실험 → 대화 성능 비교**에서 **D04 퓨즈 획득 직후**를 선택한다. 화면의 현재 장소가 비품실이고 퓨즈를 보유했는지 확인한다. **이제 어디로 가?**를 입력해 1회 비교하고 양쪽의 원문과 시간을 읽는다.
3. 실험 전에 질문, 허용 행동, 평가 척도, 반복 횟수를 확정한다. 질문은 `game/resources/experiments/questions.json`에 ID, 질문, 적용 상황, 평가 목적, 확인할 사실을 추가할 수 있다. 질문 또는 시나리오 파일을 변경하면 시나리오 버전의 해시가 바뀐다.
4. 실험실 메뉴에서 **수집 용도 → 논문 수집**을 선택한다. D04에서 반복 횟수 **5회 → 비교 실행**을 누르면 질문 하나에 두 제공자의 결과가 각각 5건 생긴다. **전체 시나리오 → 질문 세트 실행**은 각 질문에 지정된 상황을 적용한다. 자유 질문으로 전체를 선택하면 같은 질문을 모든 상황에 묻는다.
5. **전투 지원 판단 비교 → B01 플레이어 체력 부족 → 5회 → 비교 실행**을 선택한다. 두 방식의 선택·소요 시간·허용 집합 일치·시간 내 유효성을 확인한다. 전체 8종을 한 번에 실행할 때도 1·5·10·20회 중 하나를 선택한다.
6. **전투 재현 실험**에서 C01~C03을 실행한다. 생존 또는 전멸 결과, 자원 변화와 실제 지원 완료 이벤트를 확인한다.
7. **실험 기록 확인**에서 세션과 회차를 선택한다. 대화 원문을 읽고 질문 관련성, 게임 사실 정확성, 캐릭터 일관성, 자연스러움을 각각 0~2점으로 평가한다. 미평가와 0점을 구분한다. 잘못된 사실이 있으면 체크한다. 점수 수정 이력도 남는다.
8. **세션 CSV 내보내기**로 한 세션 전체를 내보낸다. 필터는 화면의 회차 목록과 요약에 적용된다. 분석할 때는 실행 방식, 코드·시나리오 버전, 모델 설정, 적재 상태와 평가 기준이 같은 세션을 묶는다. 각 `pair_id`에서 두 제공자의 기록 수와 해시부터 확인한다.

## 재현 조건

| 모드 | 상태와 진행 | 평가 |
|---|---|---|
| 대화 D01~D10 | 미카를 만나기 전부터 격벽 신호 직후까지의 실제 Fleet 단계, 장소, 물품, 적, 관측 사건을 구성한다. | 생성 원문, 처리 주체, 응답 시간, 사람이 입력한 점수 |
| 고정 판단 B01~B08 | 월드 전체를 정지한다. 양쪽에 동일한 관측과 실제 유효 행동 목록을 제공한다. 기본 3초의 판단 기한은 실제 경과 시간으로 흐른다. | 사전 허용 집합 일치, 후보 유효성, 기한 내 유효성, 거절 사유 |
| 실제 전투 C01~C03 | B동 2차 웨이브의 선원 3명과 침식 센트리 1명, 실제 충돌·탄환·피해·지원 실행기를 사용한다. 시나리오 시작 시 한 번 지원을 요청하고, 고정 위치에서 45물리틱마다 같은 지점으로 사격을 시도한다. | 최대 12초 생존, 적 전멸 또는 플레이어 전멸, HP·탄약·키트 변화와 지원 시작·완료·거절 |

두 제공자는 매번 새 월드와 빈 대화 기억에서 시작한다. 시나리오별로 전체 회차에서 관측 해시와 적·쿨다운을 포함한 시작 상태 해시를 대조하고, 요청 직전에도 관측을 재확인한다. 불일치가 있으면 이유를 기록하고 세션을 중단한다. 제공자 순서는 회차와 상황에 따라 교차한다.

C 모드에서는 양쪽 모두 공통 긴급 지원을 끄고, 스토리 웨이브 전환과 플레이어의 수동 이동을 차단한다. 모델 응답이 늦는 동안 실제 적은 계속 공격한다. 같은 틱의 사격 시도라도 탄약·재장전 상태에 따라 발사 결과가 달라질 수 있다. 생존은 12초 관찰 종료를 뜻한다. 재현 범위는 이 입력 패턴과 전장이다.

## 데이터 위치와 읽는 법

게임 내부 기준 경로는 `user://experiments/`다. 런처로 실행하면 저장소 아래 `runtime/appdata/Godot/app_userdata/로컬 AI NPC 연구 시제품/experiments/`에 있다. 일반 Windows 실행 파일은 해당 사용자의 Godot 앱 데이터 폴더를 사용한다. 결과 화면과 CSV 저장 후 안내에서 실제 절대 경로를 확인할 수 있다.

| 폴더 | 내용 |
|---|---|
| `pilot/`, `research/` | 수집 용도 선택에 따른 예비 실험과 논문 수집 |
| `development_fixture/`, `development_live/` | 자동 검증의 모의 전송과 실제 Ollama 호출 |
| 각 용도 아래 `dialogue/`, `decision/`, `combat/` | 세션별 JSONL. 종료된 요청당 한 행, 실패·취소 포함 |
| `sessions/` | 세션 조건, 요청 시작 상태, 종료 기록, UTF-8 BOM을 포함한 CSV |
| `ratings/` | 요청 ID에 연결한 수동 평가. 화면과 CSV에는 가장 최근 평가 적용 |

- `experiment_id`는 요청 하나, `pair_id`는 같은 질문·상황·회차의 두 조건을 식별한다. 게임 내부의 숫자 `request_id`는 해당 월드 안에서 사용한다.
- `initial_state.game`은 NPC 관측, `initial_state.world`는 위치·적 체력·공격 대기시간·자원을 포함한 실제 시작 상태다. `observation`과 `allowed`는 고정 판단의 공통 관측과 후보를 확인하는 데 쓴다.
- `accepted`, `appropriate`, `timely_valid`를 따로 읽는다. 자동 선택한 `follow`와 `wait`는 현재 지시를 유지하는 정상적인 `no_change`가 될 수 있다. 늦게 반환된 행동도 `selected_action`, 실제 시간, 허용 집합 일치 여부를 남긴다.
- `elapsed_ms`는 대화에서 호출부터 결과 통보까지, 판단에서 판단기가 기록한 반환까지의 시간이다. `display_ready_ms`는 표시 가능한 대화를 받은 시점이다. 실제 전송 이전의 적재 상태 조회는 제외한다. 통신 시간초과와 취소는 측정된 경과 시간을 보존한다. 결과 요약의 시간 분모는 시간이 관측된 요청 수이며, 적절률·시간 내 유효 판단률의 분모는 해당 그룹의 전체 요청 수다.
- `response_text`에는 표시한 대사나 거절된 생성 대사가 남는다. `attempts`에는 개별 전송의 프롬프트·원문 또는 부분 응답·서버 지표가 있다. `validation_errors`는 재생성 이유를 담는다. 생성 실패를 규칙 응답으로 대체하지 않는다.
- `dialogue_method=executor_receipt`와 `actual_model=common_executor`는 명시적 명령 영수증이다. 자유 대화 평균 점수에는 성공한 자유 응답 중 실제 평가가 있는 건만 들어간다.
- `model_readiness`는 요청 전 Ollama 조회 결과다. 메모리 상주 여부와 조회 가능한 모델 digest·양자화 정보를 보존한다. 서버에 연결할 수 없으면 준비 상태는 미확인으로 남는다.
- `combat.events`의 시작·완료 시각, 물리틱, 실행 주체로 효과를 추적한다. `resource_uses_without_observed_effect`는 회복·보급 효과가 0이거나 관찰 종료까지 치료량이 0인 장비 설치 횟수다. 이 값은 해당 전투의 관찰 기간에 한정된다.
- 강제 종료로 시작 이벤트만 남은 요청은 조회와 CSV에서 `unfinished`로 표시한다. 이 경우 관측하지 못한 응답과 시간을 비워 둔다. 원본 JSONL과 평가 파일을 CSV와 함께 보관하면 세션을 다시 확인할 수 있다.

## 변경 파일

- `game/scenes/experiments/ExperimentHub.tscn`, `game/scripts/experiments/experiment_hub.gd`에 모드 선택, 비교 화면, 평가·필터·내보내기를 구현했다.
- `scenario_factory.gd`, `experiment_runner.gd`, `experiment_store.gd`, `experiment_summary.gd`는 같은 스크립트 폴더에서 상태 구성, 실행, 저장, 집계를 담당한다.
- `game/resources/experiments/scenarios.json`, `questions.json`에 21개 상황과 기본 질문 10개를 정의했다. `game/export_presets.cfg`에 두 데이터 파일의 내보내기를 추가했다.
- `game/scenes/NPCBrain.tscn`을 분리하고 `game/main.tscn`에서 같은 노드 구성을 인스턴스화한다. `npc_brain.gd`, `local_ai_client.gd`는 실험실이 원본 이벤트와 각 생성 시도를 관측할 신호를 제공한다.
- `game/scenes/ui/TitleMenu.tscn`, `game/scripts/title_menu.gd`에 이어하기 아래 실험실 버튼과 복귀 처리를 추가했다.
- `game/tests/experiment_lab_test.gd`와 `scripts/verify_mission.ps1`에 헤드리스·숨김 GPU·실모델 검사를 연결했다. 기존 튜토리얼 회귀의 손전등 경로 판정은 `blackout_goal_check.gd`를 `harin_live_test.gd`, `local_integration.gd`에서 공유한다.
- `mika_dialogue.gd`에서 기존 튜토리얼의 손전등 소유자 질문에 현재 소유 주체를 밝히도록 보완했다. 해당 실모델 응답에는 별도 프롬프트 버전을 기록한다.

## 검증과 한계

저장소 루트의 PowerShell에서 `.\scripts\verify_mission.ps1`로 기본 검사를 실행한다. `-Render`는 숨김 GPU 검사와 PNG를, `-LocalAI`는 실제 모델 호출을 추가한다. 기존 미커밋 증거가 있으면 AGENTS.md의 격리 복사 절차를 따른다. 추가 검사의 결과는 검사 복사본의 `evidence/experiment_lab/`에 있다.

고정 상태 판단의 수락은 효과 완료를 보장하지 않는다. 실효성은 C 모드에서 확인한다. C 모드는 정지 사격 패턴 하나와 한 번의 지원 요청을 측정한다. 반복 대화의 기억 유지와 사용자 파일을 고르는 시나리오 가져오기 UI는 후속 기능이다. 사람 플레이, 실제 키보드의 한글 IME 조합과 독립 평가자의 대화 점수는 자동 검사 범위 밖이다.

2026-11-20 개발 검증에서 헤드리스 91개, 1280×800 및 960×600 숨김 GPU 96개, 내보낸 Windows PCK의 헤드리스 검사 91개가 통과했다. 실험 전후 같은 본편 슬롯의 SHA-256을 확인하고 이어하기와 새 게임을 각각 실행했다. 실제 Windows 실행 파일은 기본 타이틀 기동까지 확인했다. PCK 회귀 검사는 같은 PCK를 읽은 Godot 검사 런타임에서 수행했다.

로컬 `qwen3:4b` 통합 검사 32개가 통과했다. 개발용 13쌍, 26건의 원본 JSONL과 세션 CSV를 별도로 대조했다. 모든 쌍의 초기 상태·후보가 일치했고, 한국어 질문·답변, 행동, 개별 생성 시도와 전투 이벤트가 내보낸 파일에 보존됐다.

| 실모델 개발 검증 | RuleBased | LocalLLM |
|---|---|---|
| D04 “이제 어디로 가?” 각 5회 | 5회 응답, 평균 0.420 ms | 5회 응답, 평균 34.939초 |
| B01 체력 부족 각 5회 | 5회 모두 기한 안에 치료 선택, 평균 0.050 ms | 5회 모두 기한 안에 치료 선택, 평균 252.112 ms |
| C03 복합 위기 각 1회 | 치료 1회 완료 | 보급 1회 완료 |

C01~C03의 여섯 전투에서는 모두 실제 지원이 끝난 뒤 플레이어가 전멸했다. 이 수치는 이번 개발 검증의 고정 입력·모델·PC 조건에서 관측한 값이다. 논문용 대화 점수는 수집하지 않았다.

검사 사본과 생성 파일은 저장소의 `runtime/npc_experiment_lab/` 아래에 있다. 최종 실험실의 `fixture.json`, `gpu.json`, `live.json`, `export_audit.json`은 `final_project/evidence/experiment_lab/`에 있다. 본편 전체 기본·렌더 검사는 `final_project/evidence/suite.log`로 확인할 수 있다. 초기 전체 실모델 검사는 튜토리얼 회귀에서 중단되어 원문을 보존하고 후속 검사를 각각 실행했다. 손전등 보완 후 미카 실모델 검사 39개와 실제 치료·보급·장소 변경 시 폐기·현재 경로 검사 6개가 통과했다.

기존 Fleet 실모델 검사에서는 퓨즈 탐색을 시작한 직후 미카가 아직 확인하지 않은 오른쪽 캐비닛을 지목한 응답도 관측했다. 실제 퓨즈는 왼쪽 캐비닛에 있다. 이런 응답의 사실 정확성은 수동 평가 항목에 기록한다. 원문은 격리 검사의 `evidence/fleet_dialogue/live_suite.json`에 있다.
