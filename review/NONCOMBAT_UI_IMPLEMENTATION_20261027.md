# 비전투 대화 화면 1단계

네 장은 디자인 참고 자료로만 사용했다. 이번 적용 범위는 `버려진 우주 연구소의 하린 대화-1.png`를 참고한 비전투 대화 화면이다. 전체 참고 이미지를 배경이나 UI 텍스처로 붙이지 않았다. 맵 배치·스폰·충돌·전투 수치·LLM 프롬프트는 유지했다.

## 새 그림과 코드 구분

| 요소 | 구현 방식 | 현재 적용 |
|---|---|---|
| 하린 상반신 | 새 투명 PNG 한 장 | `game/assets/ui/harin_bust_v1.png`, 1086×1448 RGBA. 내장 image_gen으로 생성, 원본 알파 유지 |
| 큰 대화 패널 | Panel + 개별 장식 Control | 잘린 모서리·금속 음영·나사·호박색 선을 `IndustrialUIFrame`으로 그림 |
| 이름·대사·상태 | Label / RichTextLabel | 이름은 NPC 표시명, 본문은 기존 답변 신호, 상태는 입력·대기·오류에 연동 |
| 입력창 | 기존 ChatInput (TextEdit) | 같은 노드와 Windows 확정 입력 DLL 재사용. 마지막 글자 확정·300자 제한·중복 전송 방지 유지 |
| 전송·닫기·재열기 | 실제 Button | 기존 요청 함수 또는 대화창 표시 상태에 연결. 글자는 Button.text |
| 하린 위 상태 말풍선 | Control + Label | 인물의 실제 화면 좌표를 따라가는 대화 가능/응답 대기 표시. 자동 NPC 발화나 화면 밖 호출은 아님 |
| 우측 목표 | Panel + Control + Label | 퓨즈·전력·완료 상태에 따라 실제 목표 갱신 |
| 체력바 | 기존 ProgressBar 유지 | 시안 2의 전투용 표현 변경은 다음 단계 |
| 맵·이동 캐릭터 | 기존 시제품 자산 유지 | 최종 SF 픽셀 타일·캐릭터·애니메이션은 별도 작업 |

새 초상화는 UI에만 사용한다. 제작 방법과 전체 프롬프트는 `game/assets/ui/HARIN_BUST_SOURCE.md`에 있다. 입력창·패널·버튼용 그림을 별도로 생성하지 않았다.

## 동작

- 연구실에서 큰 대화창을 표시하되 처음부터 입력 포커스를 강제하지 않는다.
- Enter 또는 하린 근처 E로 입력한다. 입력 중 Enter는 기존 `request_submit → _send_question → brain.request_dialogue`를 그대로 사용한다.
- 비전투에서 Esc/닫기 버튼으로 닫고, Enter/하단 버튼으로 다시 연다. 미전송 문장은 유지한다.
- 조합 중 첫 Esc는 기존 조합 취소다. 조합이 없을 때만 새 `editing_closed` 신호로 창을 닫는다. ChatInput의 변경은 이 신호뿐이다.
- AI 대기 중 닫아도 요청을 취소하지 않는다. 닫힌 동안 받은 답변·오류는 보관하며 창을 강제로 열지 않는다. 대기 중 입력은 읽기 전용이고 재열어도 입력 포커스를 강제로 주지 않는다.
- 긴 대사는 원문을 유지하고 RichTextLabel 안에서 스크롤한다.
- 연구실 또는 드론이 모두 제거된 상태에 새 비전투 배치를 사용한다. 드론이 남은 보관 구역에서는 기존 전투 화면과 작은 통신 UI로 복귀한다. 노드를 새로 만들거나 AI·IME 모듈을 중복 연결하지 않는다.
- 초기 안내 문장은 공통 임무 상태 템플릿이다. LLM 실호출 결과로 제시하지 않는다. 입력한 질문의 답변은 선택한 기존 제공자 경로에서 받는다.
- F3 실험 설정은 유지한다. Esc 일시정지 메뉴는 이번 작업에 포함하지 않는다.

## 편집 위치

`game/main.tscn → RadioPanel` 아래 `LabPortrait / CompanionName / Answer / Question / SendButton / CloseDialogue / KeyHint / LabChrome`은 개별 저장 노드다. `Question`과 `SendButton` 아래에는 각각 별도 테두리 Control이 있다.

`RadioPanel` Inspector의 `Noncombat Mode`, `Dialogue Height`, `Portrait Width`로 배치를 미리 본다. 나머지 반응형 배치 기준은 `noncombat_dialogue_panel.gd`에 모아 두었다. 버튼·대사 영역의 좌표는 이 배치 정책이 적용한다. 글꼴·색·여백은 `LabDialogueTheme.tres`, 금속 장식 색은 각 `IndustrialUIFrame`의 내보낸 속성으로 조정한다.

## 검증과 한계

기존 129개 + 비전투 전용 42개 = 171개 자동 검사. 비전투 검사는 열기·닫기·초안 보존·기존 전송 경로·대기/오류·스크롤·한 노드 재사용·모드 왕복·클릭 오발 방지·960×600 논리 캔버스를 다룬다. Windows IME DLL의 SHA-256은 `72082b7d2f61f9b1f2435be8f70f2012ccb63d656dd73c3d12ba6777c66851a6`로 이전과 같다.

사용자의 화면 조작 금지를 지켜 헤드리스 코드 검사만 수행했다. 실제 Microsoft IME·GPU 렌더링·다른 창 크기의 사람 검증은 이번 검사에 포함되지 않는다. LLM 실호출은 새로 하지 않았다. `local_ai_client.gd`, `npc_brain.gd`, 제공자 설정과 네이티브 DLL의 통신·입력 구현은 수정하지 않았다.

`evidence/noncombat_ui/noncombat_open_preview.png`와 닫힌 상태·작은 캔버스 미리보기는 씬 위치/테마/에셋의 정적 재구성이다. 실제 게임 캡처가 아니며 픽셀 조판·셰이더·스크롤바를 완전히 재현하지 않는다. 배경은 현재 도형 시제품이므로 첨부 시안의 완성된 연구소 배경과 다르다.

## 이후 순서

1. 전투 HUD: 실제 플레이어 상태에 연결한 개별 체력·탄약 표시. 현재 하린은 무적이므로 가짜 체력·탄약을 만들어 표시하지 않는다. 하린 전투 자원 규칙이 필요하면 먼저 게임 규칙을 정한다.
2. 화면 밖 대화: 실제 NPC 화면 밖 위치·발화 이벤트에 연결한 방향 표시·소형 통신 카드. 이번 초상화를 재사용할 수 있다.
3. ESC 메뉴: 실제 일시정지·설정·복귀 기능부터 연결한다. 시안의 저장/불러오기 버튼은 저장 시스템이 구현된 뒤 연결한다. 웃는 하린 전신 그림이 필요하면 별도 제작한다.
