# 미카 대화 프로필과 응답 시간 측정

## 실행과 평가

1. `START_LOCAL_AI.cmd`를 실행한다. 타이틀에서 **NPC 실험실 → Qwen 대화 프로필 실험**을 연다. 예비 실험을 먼저 실행하고 논문용 회차를 시작할 때 홈에서 **수집 용도 → 논문 수집**을 선택한다.
2. **A·B·C 교차 비교** 또는 개별 프로필을 선택한다. D04의 “이제 어디로 가?”, D01의 “미카, 오늘 좀 피곤해.”와 “저녁 뭐 먹을래?”처럼 같은 상태에서 같은 질문을 비교한다. 한 번에 1·5·10·20회를 선택할 수 있다. 교차 비교는 회차와 질문마다 실행 순서를 회전한다. 개별 실행에서도 처음 상태와 빈 대화 기억을 복원한다.
3. **프로필 응답 블라인드 평가**에서 세션을 연다. 회차 목록은 무작위로 발급한 식별자 순서로 정렬한다. 채점 전에는 질문과 원문을 보여 준다. 사실 정확성·질문 관련성·캐릭터 일관성·자연스러움을 0~2점씩 입력하면 해당 답변의 프로필과 시간이 공개된다. 거절된 완성 원문도 읽고 평가할 수 있다. 미평가 값은 `null`이다. 운영자가 실행 순서를 알고 있는 경우 독립 평가자에게 기록 화면만 제공한다.
4. **세션 CSV 내보내기**로 세션 전체를 저장한다. 원본과 CSV는 `user://dialogue_optimization/<용도>/`에 있다. 런처 기준 실제 위치는 `runtime/appdata/Godot/app_userdata/로컬 AI NPC 연구 시제품/dialogue_optimization/`이다. 용도는 `pilot`, `research`이며 자동 검사는 격리 사본의 `development_fixture`, `development_live`를 사용한다. 원본 요청은 `dialogue/`, 실행 조건과 CSV는 `sessions/`, 화면 표시 이벤트는 `presentation/`, 수동 평가는 `ratings/`에 있다.

본편에서 수신 최적화와 새 캐릭터 프롬프트를 함께 사용하려면 `.\scripts\start_demo.ps1 -Provider LocalLLM -DialogueProfile C_FAST`로 실행한다. Godot 편집기에서는 `NPCSettings.tres`의 **Campaign Dialogue Profile**에서 고를 수 있다. 기본은 A다. 일반 NPC 비교 실험실은 본편의 프로필 선택과 독립적으로 기존 비교 조건을 사용한다.

## 비교 조건

모델은 동일한 로컬 `qwen3:4b`이고 대화 온도는 0.55, 시드는 42, `keep_alive`는 15분이다. A는 기존 리소스 값을 그대로 읽는다. 다음은 이 저장소 기본값이다.

| 프로필 | 요청한 Thinking | 출력 한도 | 문맥 | 프롬프트와 출력 |
|---|---|---:|---:|---|
| A | ON | 4096 | 8192 | 기존 대화 프롬프트와 발화 |
| B | OFF | 256 | 8192 | A와 동일한 역할 메시지 |
| C | OFF | 256 | 8192 | 미카의 캐릭터 프롬프트와 발화 |
| B512 / C512 | OFF | 512 | 8192 | 각각 B / C의 출력 한도 실험 |
| C4096 | OFF | 256 | 4096 | C의 문맥 길이 실험 |
| C_ON | ON | 4096 | 8192 | 기존 생성 설정에서 캐릭터 프롬프트만 교체 |
| C_FAST | ON | 4096 | 8192 | C_ON과 같은 메시지·생성 설정. 한 프레임에서 이미 도착한 HTTP 조각을 최대 32개, 약 1.2ms 한도에서 비동기로 읽는다. |
| D | OFF | 256 | 8192 | 캐릭터 프롬프트와 `dialogue` 문자열 한 개를 가진 JSON 출력. 스키마는 지문 괄호와 줄바꿈을 제외하고 1~150자를 요청한다. |

C 계열은 개척선 정비사와 친한 동료라는 관계를 먼저 제시한다. 피곤하다는 말에는 잠깐 쉴 틈을 챙기는 가상 말투 표본을, 식사에는 기존 자료의 관련 말투 한 건을 사용할 수 있다. 일상 질문에는 임무 목록을 넣지 않는다. 임무 질문은 해당 단계에서 관측한 사실과 다음 행동을 사용하고, 위급할 때는 짧게 말하도록 한다. 원래 예시 데이터, 규칙 기반 답변, 전투 후보·JSON·48토큰·온도 0.1·기본 3초 기한은 기존 구현을 사용한다.

수송 실패, 빈 출력, 길이 제한 또는 대사를 분리할 수 없는 출력은 실패로 남긴다. 완성된 대사가 기존 의미 검증에 실패하면 같은 프로필로 한 번 재생성한다. 연구 기록은 최초 실패 사유와 모든 시도를 보존한다. 공통 명령 영수증은 해당 처리 주체로 표시하고 자유 대화 평가에서 제외한다.

같은 조건의 회차를 묶을 때는 `profile_id`, `profile_version`, `prompt_version`, `project_fingerprint`, 모델 digest와 실제 옵션을 함께 확인한다. A와 B는 의도적으로 같은 프롬프트 버전을 사용한다. C_ON과 C_FAST도 프롬프트와 Ollama 요청 설정이 같고 Godot 수신 방식이 다르다.

## 지표와 단위

- `elapsed_ms`는 Godot 요청 시작부터 최종 수락·거절·실패까지의 실시간이다. 재생성 대기 시간도 포함한다. `first_dialogue_ms`는 전체 요청에서 처음 수신한 비공백 대사 조각이고 `final_attempt_first_dialogue_ms`는 수락된 마지막 시도의 첫 대사다. 화면에 쓸 대사가 없으면 빈 값이다.
- `display_ready_ms`는 검증한 대사를 표시할 수 있는 시점이다. `screen_display_ms`는 같은 답변이 결과 카드에 들어가고 해당 카드가 보이는 프레임의 렌더 완료까지다. 헤드리스, 가려진 카드, 렌더를 확인할 수 없는 회차는 비운다. 숨김 GPU 자동 검사는 프레임 갱신을 요청한다. 물리 모니터의 스캔아웃이나 사람이 읽기 시작한 시각은 측정하지 않는다.
- `attempts[].metrics`에 Ollama가 보고한 `prompt_eval_count`, `eval_count`, `load_duration`, `prompt_eval_duration`, `eval_duration`, `total_duration`을 보관한다. 서버 duration은 나노초, Godot의 `*_ms`는 밀리초다. `server_totals`는 모든 시도의 합이며 한 시도라도 누락된 지표는 비운다. `eval_count`와 `eval_duration`에는 모델이 생성한 추론도 포함될 수 있다.
- `attempts[].first_thought_ms`와 `last_thought_ms`는 Godot가 추론 조각을 관측한 시각이다. 서버가 분리해 준 추론과 확인 가능한 인라인 경계를 사용한다. 최초 대사 도착 전 대기에는 연결·로딩·입력 처리도 포함되므로 이 구간 전체를 내부 추론 시간으로 부를 수는 없다.
- 요청한 `model_thinking`과 모델이 광고한 `model_thinking_values`를 함께 읽는다. `/api/show` 조회, `/api/ps`의 적재 여부·digest·GPU 메모리를 기록한다. 적재 상태 조회는 실험실 요청 타이머 시작 전에 수행한다. GPU 재확인은 저장소에서 `runtime\ollama\ollama.exe ps`, PowerShell의 `Invoke-RestMethod http://127.0.0.1:11434/api/ps`로 할 수 있다.

## 개발용 실측 결과

기본 세 질문은 D04 “이제 어디로 가?”, D01 “미카, 오늘 좀 피곤해.”와 “저녁 뭐 먹을래?”다. A·B·C는 질문마다 두 번, C_ON·C_FAST 수신 비교는 각 한 번씩 생성했다. D에는 D02 퓨즈 위치와 D08 레버 신호 질문도 포함했다. 평균과 중앙값의 분모는 실패·재생성을 포함한 전체 요청이다. 첫 대사와 렌더 열은 값이 관측된 요청의 평균이다. 단위는 초다.

| 조건 | 수락/요청 | 종료까지 평균 | 중앙값 | 첫 대사 | 수락 대사 렌더 |
|---|---:|---:|---:|---:|---:|
| A 기존 | 6/6 | 32.54 | 30.93 | 32.32 | 32.57 |
| B 기존 프롬프트 OFF | 0/6 | 4.34 | 4.35 | — | — |
| C 캐릭터 프롬프트 OFF | 0/6 | 4.63 | 4.24 | — | — |
| C_ON 기존 수신 | 3/3 | 38.79 | 33.38 | 38.56 | 38.81 |
| C_FAST 개선 수신 | 3/3 | **16.58** | **18.78** | **16.44** | **16.60** |
| D 구조화된 대사 | 2/5 | 1.64 | 1.67 | 0.21 | 0.91 |

C_ON과 C_FAST에 보낸 역할 메시지, 모델 옵션, 시작 상태가 각 쌍에서 같았다. 평균 전체 대기는 22.21초(57.3%) 줄었다. Ollama의 평균 출력 생성 시간은 각각 15.03초와 16.41초였다. 프레임당 한 조각만 소비하던 클라이언트에서 대기가 누적됐다. C_FAST에서는 관측된 추론 조각의 첫 시각부터 마지막 시각까지 평균 16.25초, 수락된 첫 대사 조각부터 최종 응답까지 평균 0.14초였다. 숨김 GPU 창에서 측정한 세 질문이므로 다른 PC와 질문에도 같은 비율이 적용된다고 단정할 수 없다.

실제 입력은 A·B에서 619~831토큰, C 계열에서 212~242토큰이었다. D04를 C4096으로 다시 실행해 입력 241토큰을 확인했다. 4096 문맥에도 이 질문은 들어갔지만 256 출력 한도를 소진했다. B512·C512도 같은 질문에서 각각 512토큰을 사용하고 최종 대사를 완성하지 못했다. 이 표본으로 장시간 대화 기억까지 평가하지는 않았다. 기본 문맥은 8192다.

**미카의 실제 발화.** C_FAST는 D04에서 “비품실 아래 문으로 나가 오른쪽 전기실로 가자. 퓨즈는 네가 갖고 있어.”라고 답했고, 저녁 질문에는 “네가 쏘는 거야? 그럼 난 치즈 치킨... 히히”라고 답했다. 피곤하다는 말에는 “아, 쉬자. 나도 피곤해.”라고 해 짧은 반말은 유지했지만 구체적인 배려는 약했다. D는 통과한 대사에도 현재 상태에 없는 아침 날씨를 덧붙였다. D04·D08은 최종 검증 거절, 저녁 질문은 잘못된 JSON으로 실패했다. 수동 품질 점수는 모두 미평가로 두었다.

개발용 측정 자료는 저장소의 `runtime/qwen_dialogue_profiles/`에 있다. A·B·C와 문맥·출력 한도 실험은 `supplement/evidence/dialogue_profiles/audit_live_gpu.json`, 최종 C_ON·C_FAST·D는 `transport/evidence/dialogue_profiles/audit_followup_gpu.json`을 참조한다. 두 검산에서 원본과 CSV의 29행과 11행을 각각 대조했다. 개발 중 D 버전이 바뀌어 표의 D 수치는 마지막 검산의 5행만 사용했다. 실제 한국어 문답·CSV 파일 위치는 같은 폴더의 `live_gpu.json`과 `followup_gpu.json`에 기록돼 있다.

최종 프로필 회귀는 헤드리스 34개, 숨김 GPU 960×600과 1280×800에서 각 42개를 통과했다. 수신 방식 대조와 최종 D의 실제 호출·CSV 검사는 14개를 통과했다. 앞선 29행 측정에서는 끝 화면 PNG 검사 2개가 실패해 결과를 보존했다. 이후 컨테이너 배치와 프레임 갱신을 기다려 두 해상도에서 PNG 크기와 평가 화면을 재확인했다. 헤드리스 결과에는 렌더 시각이 비어 있으며, 숨김 GPU 결과에는 다음 요청 전 확인한 프레임 시각이 들어간다.

## 회귀 검사에서 관측한 대사 오류

기존 A의 Fleet 실모델 30개 검사 중 두 항목이 최초 실행에서 실패했다. 미카를 만나기 전의 통신 상태 질문에서 “통신 끊겼어?”라고 했고, 전투 중 레버 질문에서는 미카의 신호 조건을 생략했다. 기존 사실 검증이 두 답변을 거절했다. 실패한 원문과 재생성을 보존했으며, 두 사례의 개별 재실행에서는 각 3개 검사가 통과했다.

기존 미카 실모델 검사에서는 실제 대기 명령이 유지되는데도 상태 질문에 “물론이야! 떠나면 뒤에서 보이지 않아? 히히”라고 답했다. 39개 중 대기 상태 설명 1개가 실패했다. 대기 명령 실행기와 A의 프롬프트는 기존 비교 조건을 따른다. 이처럼 모델의 응답 수락 횟수와 사람이 읽은 사실 정확성은 별도로 집계해야 한다.

기존 본편 기본·숨김 GPU 회귀와 NPC 비교 실험실의 헤드리스 91개, GPU 96개, 실제 로컬 모델 32개가 통과했다. 전체 실모델 명령은 위 Fleet 실패에서 중단되어 이후 검사를 각각 실행했다. 봉쇄 7개, 서사 대화 15개, 저장·취소 7개, 기믹 11개, 대화 품질 20개 및 실제 치료·보급·맵 변경 취소 통합 검사가 통과했다. 실제 사람의 플레이나 독립 평가자의 주관적 점수는 수집하지 않았다.
