# 로컬 AI 동료 NPC 졸업작품

2026-10-26 기준 현재 버전은 **연구실 왕복 임무 + 동료 하린 + 세 가지 판단 방식**을 비교하기 위한 시제품이다.
UI는 먹색·청록·호박색의 SF 통신 장비 분위기로 구성했다. Canva 플러그인으로 만든 하린의 픽셀 초상화를 통신창에 적용했다. 맵의 소품과 이동 캐릭터는 아직 기능 확인용 도형이다. 최종 타일·캐릭터·걷기 애니메이션은 다음 작업이다.

## 실행

GitHub에서 처음 받은 PC는 [SETUP_RUNTIME.md](SETUP_RUNTIME.md)에 따라 Godot와 선택한 AI 실행 환경을 준비한다. 실행 파일·모델은 Git에 포함하지 않으며, 버전·공식 다운로드 URL·해시는 `runtime/tools_manifest.json`에 기록했다.

- `START_DEMO.cmd`: 기본 규칙 기반 NPC. 외부 API 키 없이 플레이한다.
- `START_LOCAL_AI.cmd`: Ollama를 준비하고 로컬 LLM NPC로 실행한다.
- `START_JEV.cmd`: Jev 모드. 실행 환경에 `TYPESAFE_API_KEY`가 있어야 실제 판단이 가능하다.
- `OPEN_PROJECT.cmd`: Godot 편집기. 수정한 뒤 F5로 전체 게임을 실행한다.
- `VERIFY_MISSION.cmd`: 새 왕복 임무의 자동 기능 검사.

게임 상단의 **실험 설정 / F3**에서 규칙 기반 / 로컬 LLM / Jev를 선택하고 새 회차를 시작할 수 있다. **방식을 변경하면 동일한 초기 조건으로 새 회차를 시작한다.** 현재 방식은 오른쪽 아래에 표시한다.
로컬 모드로 바꾸기 전에 서버가 준비되지 않았다면 `START_LOCAL_AI.cmd`로 실행한다. 오류를 다른 방식의 성공 결과로 대체하지 않는다.

현재 로컬 모델은 이미 설치된 **Qwen3 4B (`qwen3:4b`)**다. Ollama의 `think=false`와 행동·대사의 JSON 스키마를 함께 사용한다.
기존 Qwen2.5 1.5B는 개발 점검에서 긴급 치료·보급 대신 보호 장비를 우선 고르는 사례가 있어 기본 모델을 변경했다. 이것은 소수 개발 사례에 따른 임시 선택이며 모델 우열에 대한 본 실험 결론이 아니다.
초기 Qwen3의 비구조화 대사에서 생각 과정·길이 제한 문제가 있었던 기록과 이번 개발 실패 기록은 보존했다. 구조화된 대사도 말투·사실 일관성의 추가 평가가 필요하다.

## 조작과 임무

- WASD / 방향키: 이동
- E: 가까운 물체 상호작용. 하린에게 사용하면 질문 입력창에 포커스
- 마우스 왼쪽 클릭: 커서 방향 사격
- Space: 현재 원형 시야 안의 가장 가까운 적을 조준해 사격
- Enter: 질문 입력, 입력 중 Enter로 전송
- 입력 중 Esc: 입력창에서 빠져나와 이동
- F3: 판단 방식·재시작·요청 지연·현재 모델·판단 수락 여부 등 실험 설정
- F12: `evidence/mission_v1/manual.png` 저장
- 실험 설정 → 새 회차 시작: 적·아이템·자원·회차 대화 기억 초기화

통신창의 **임무 확인 / 지원 요청 / 일상 대화**는 질문 초안만 입력한다. Enter 또는 전송으로 보낸다. 작성 중인 문장은 덮어쓰지 않는다. 설정창이 열려 있거나 질문에 포커스가 있을 때는 플레이어 이동이 멈추며, 전투는 계속된다. 통신 상태의 대기/입력 중/응답 중/오류는 실제 입력·요청 상태를 나타내며 네트워크 연결 성공을 뜻하지 않는다.

연구실 → 오른쪽 통로 → 어두운 보관 구역 → 드론 3기 제압 → 북동쪽 퓨즈 회수 → 왼쪽 통로로 연구실 복귀 → 전력 장치에 퓨즈 장착 → 출구로 완료.

보관 구역에서는 플레이어 주변의 원형 영역만 보인다. 초기 탄약이 제한되어 있으며, 하린의 보급 외에 진입부의 비상 탄약함을 한 번 사용할 수 있다.
하린은 동행하며 상황에 따라 치료, 탄약 보급, 보호 장비 설치, 보호 지점으로의 방향 안내를 선택한다. 보호 장비 안에서는 기본적으로 피해가 절반이 된다.
치료 키트 2개, 보급품 2개, 보호 장비 1개를 세 방식에 동일하게 제공한다. 방을 왕복해도 사용한 자원이 재생되지는 않는다.

질문 입력 중에는 플레이어 이동만 멈춘다. **적과 전투는 계속된다.** 질문 전송 후에는 즉시 이동할 수 있다.
한글 입력창은 TextEdit 기반이다. 입력 중 본문·커서·선택 범위를 재설정하지 않고, 전송 전에 조합 글자를 확정한다. 300자를 넘는 내용은 전송을 막고 입력을 그대로 유지한다.
2026-10-26부터 Windows에서는 전용 확정 입력 연결 모듈을 함께 사용한다. DLL은 game/native/windows_ime에 포함되며 일반 실행에 별도 컴파일러가 필요하지 않다. 변경 후에는 게임을 완전히 닫고 다시 실행해야 한다. 상세 내용은 review/CHAT_INPUT_NATIVE_FIX_20261026.md와 native/windows_ime/README.md 참조.
추론 대기 중에도 게임 상태를 바꿀 수 있다. 맵 전환·사망·재시작 전의 답변은 폐기하며, 지원 판단은 응답 시점에 유효한지 다시 검사한다.

## 세 방식의 차이

| 방식 | 지원 행동 | 질문 답변 |
|---|---|---|
| RuleBased | 체력·탄약·전투 상태에 따른 고정 우선순위 | 키워드 의도 분류 + 준비된 문장 |
| LocalLLM | 같은 관측 정보와 유효 후보에서 구조화된 행동 선택 | 현재 임무·동료 관계·짧은 회차 기억을 바탕으로 자유 대사 생성 |
| Jev | 공식 Choice API로 같은 후보에서 선택 | 질문 의도 선택 + 준비된 문장 |

Jev 자체를 자유 대화 생성 모델로 간주하지 않는다. Jev에 LLM을 추가하는 경우는 별도 혼합 방식이다.
현재 Jev 어댑터·스키마·키 누락 처리는 구현했으나, **실제 API 인증/추론은 0회**다. 한 프로세스 실행의 Jev 호출 상한은 기본 60회다.
키 누락·인증 오류·호출 제한 등에서는 자동으로 다른 제공자로 바꾸지 않고 오류를 표시·기록한다.

행동 실행은 모두 `world.gd`의 같은 경로를 사용한다. 하린의 기본 이동, 치료량, 탄약량, 접근 거리, 장비 지속 시간, 자원 소비는 제공자에 따라 달라지지 않는다.
대화에서 “치료했어”라고 말하는 것만으로 체력이 바뀌지 않는다. 실제 효과는 유효한 지원 행동이 완료되어야 발생한다.

## 검증과 증거

2026-10-25 현재:
- 새 임무의 자동 기능 검사 **50/50** 통과.
- 규칙 기반 실제 렌더링에서 연구실 → 전투 → 퓨즈 → 복귀 → 전력 복구 → 완료 통과.
- 실제 로컬 LLM 통합 검사 **5/5** 통과: 치료 적용, 보급 적용, 추론 중 이동, 맵 전환 후 이전 응답 폐기, 임무 대사 경로 안내.
- 로컬 모델의 고정 입력 개발 점검 6건에서 행동 3건과 대화 3건의 응답을 관찰했다. 이는 본 논문 실험이나 사람의 플레이 검증을 대신하지 않는다.
- Jev는 응답 모양의 합성 예제와 키 없는 동작만 검사했다. 실제 Jev 추론 성공을 뜻하지 않는다.

PowerShell에서:
```powershell
.\scripts\verify_mission.ps1
.\scripts\verify_mission.ps1 -Render
# 로컬 서버 준비 후, 실제 모델을 호출하는 추가 검사
.\scripts\verify_mission.ps1 -LocalAI
```

새 검사 소스는 `game/tests/`에 있다. 루트 `tests/`의 이전 단일 방 검사 파일은 보존한 과거 사양으로, 현재 검증 명령은 아니다.
추가 채팅 회귀 검사는 `game/tests/chat_input_test.gd`이며, 기본 검증 명령에 함께 포함한다. 결과는 `evidence/chat_input_fix/chat_input_test.json`에 저장한다. 합성 Unicode/조합 검사이며 실제 Windows IME 자동 조작은 수행하지 않았다.
UI 회귀 검사 35개는 `game/tests/ui_layout_test.gd`이며 기본 검증에 포함한다. 초안 보존, 응답·오류 상태, 설정창 제어, HUD 클릭 시 오발 방지, 플레이 영역 클릭 사격, 실제 체력·탄약·목표 표시, 1280×800 배치를 검사한다. `evidence/ui_redesign/ui_layout_preview.png`는 씬 위치·테마를 SVG로 재구성한 정적 미리보기이며 실제 GPU 화면 캡처가 아니다. 화면 자동 조작과 실제 입력기·다른 해상도의 육안 검사는 이번 UI 작업에서 수행하지 않았다.
이전 소스 전체는 `review/mission_before_20261025.zip`에 보관했다.

주요 결과:
- `evidence/mission_v1/mission_test.json`
- `evidence/mission_v1/01_lab.png` ~ `06_completed.png`: 실제 렌더링 자동 시연. 상태 일부를 자동으로 설정하므로 사람 플레이 증거로 간주하지 않는다.
- `evidence/mission_v1/local_integration/`: 실제 모델의 지원 적용 검사와 렌더링 화면
- `evidence/mission_v1/provider_probe/`: 개발용 고정 입력 점검. 프롬프트 변경 전후·모델·실패·연결 제약 사례를 포함하므로 합쳐 집계하지 않는다.
- `npc_events.jsonl`: 회차·제공자·입력 스냅샷·후보·선택·지연·수락/폐기·실제 효과 이벤트
- `npc_sessions.jsonl`: 로컬 요청 원문, 생성 옵션, 스키마, 실제 응답, Ollama 지표

이벤트의 `accepted`는 실행 요청 또는 대사 전달이 수락되었다는 뜻이다. 행동 적절성·문장 품질이 정답이라는 뜻이 아니다.
실제 효과는 `support_completed`로 확인한다. 대사는 JSON 전체를 검증한 뒤 표시하므로 첫 전송 토큰과 화면에 답변이 보인 시간은 다르다.
