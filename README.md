## 실행

Windows x64 배포 ZIP은 압축을 푼 뒤 `ContainmentDemo.exe`를 실행한다. 기본 규칙 기반 모드는 Godot 편집기와 Ollama 설치 없이 시작한다. 실행 파일과 PCK·DLL은 배포 폴더에 함께 둔다. [배포판 실행 안내](distribution/PLAY-KO.txt), [빌드 방법](SETUP_RUNTIME.md#windows-x64-배포-빌드), [패키지 검증 기록](review/WINDOWS_PACKAGE_20261111.md).

GitHub에서 처음 받은 PC는 [SETUP_RUNTIME.md](SETUP_RUNTIME.md)에 따라 Godot와 선택한 AI 실행 환경을 준비한다. 실행 파일·모델은 Git에 포함하지 않으며, 버전·공식 다운로드 URL·해시는 `runtime/tools_manifest.json`에 기록했다.

- `START_DEMO.cmd`: 기본 규칙 기반 NPC. 외부 API 키 없이 플레이한다.
- `START_LOCAL_AI.cmd`: Ollama를 준비하고 로컬 LLM NPC로 실행한다.
- `START_JEV.cmd`: Jev 모드. 실행 환경에 `TYPESAFE_API_KEY`가 있어야 실제 판단이 가능하다.
- `OPEN_PROJECT.cmd`: Godot 편집기. 수정한 뒤 F5로 전체 게임을 실행한다.
- `VERIFY_MISSION.cmd`: 새 왕복 임무의 자동 기능 검사.

일반 플레이는 별도의 AI 실험 로그를 작성하지 않는다. 응답 원문·프롬프트를 연구용으로 수집하려면 저장소 루트에서 `.\scripts\start_demo.ps1 -Provider LocalLLM -RecordDialogue`로 실행한다. 실험 로그는 Godot 사용자 데이터의 `evidence/mission_v1/`에 저장된다. 자동 검증은 테스트 증거 경로를 사용한다.

실행하면 타이틀 메뉴가 열린다. **새 게임**은 정전 튜토리얼부터 시작하고, **이어하기**는 기존 저장 슬롯 3개를 표시한다. 저장이 없으면 이어하기 버튼이 비활성화된다. **종료**는 게임을 닫는다.

게임 상단의 **실험 설정 / F3**에서 규칙 기반 / 로컬 LLM / Jev를 선택하고 새 회차를 시작할 수 있다. **방식을 변경하면 동일한 초기 조건으로 새 회차를 시작한다.** 현재 방식은 오른쪽 아래에 표시한다.
로컬 모드로 바꾸기 전에 서버가 준비되지 않았다면 `START_LOCAL_AI.cmd`로 실행한다. 오류를 다른 방식의 성공 결과로 대체하지 않는다.

현재 로컬 모델은 이미 설치된 **Qwen3 4B (`qwen3:4b`)**다. 자유 대화는 native thinking 후 최종 발화만 표시하고, 전술 후보 JSON은 별도 짧은 요청으로 처리한다. 필수 사건 대사와 패널 지원은 고정 사건/공통 실행기이며 모델 생성 성공으로 기록하지 않는다.
기존 Qwen2.5 1.5B는 개발 점검에서 긴급 치료·보급 대신 보호 장비를 우선 고르는 사례가 있어 기본 모델을 변경했다. 이것은 소수 개발 사례에 따른 임시 선택이며 모델 우열에 대한 본 실험 결론이 아니다.
초기 Qwen3의 비구조화 대사에서 생각 과정·길이 제한 문제가 있었던 기록과 이번 개발 실패 기록은 보존했다. 구조화된 대사도 말투·사실 일관성의 추가 평가가 필요하다.

## 조작과 임무

- WASD / 방향키: 이동
- E: 가까운 물체 상호작용. 미카에게 사용하면 질문 입력창에 포커스
- 마우스 왼쪽 클릭: 커서 방향 사격
- Space: Fleet 데모에서 이동 방향으로 회피 대시. 정지 중에는 마지막 이동 방향으로 대시하며, 연출 대사가 표시될 때는 다음 대사로 넘긴다.
- Enter로 채팅 입력창을 열고 입력 중 Enter를 다시 눌러 전송한다.
- Esc는 열린 대사 다시보기나 지도를 먼저 닫는다. 입력 중에는 한글 조합을 취소하거나 입력창을 닫는다. 플레이 중에는 일시정지 메뉴를 연다.
- F3: 판단 방식·재시작·요청 지연·현재 모델·판단 수락 여부 등 실험 설정
- F12: `evidence/mission_v1/manual.png` 저장
- 실험 설정 → 새 회차 시작: 적·아이템·자원·회차 대화 기억 초기화
- M으로 발견한 전체 지도를 연다. L로 대사 다시보기를 열고 L 또는 Esc로 닫는다.
- 미카 다운: 가까이에서 E로 치료 키트 1개 사용. 대기 해제: Enter → `따라와` 전송
- 데모 결과 화면: `다시 시작`으로 튜토리얼부터 초기화, `타이틀로 돌아가기`로 타이틀 메뉴 열기, `종료`로 게임 종료

좌측 상단에는 탐색 미니맵과 현재 목표가 표시된다. 좌측 하단에는 체력과 장탄 수가 모여 있고, Fleet 데모에서는 장탄 수 오른쪽에 예비 탄창 아이콘과 수량이 표시된다. R로 재장전하면 플레이어 머리 위에 진행 바가 표시된다. 연구실 B동의 침식 센트리는 플레이어를 조준해 직선 탄 두 발을 쏜 뒤, 붉어지는 사선에 레이저를 발사한다.

Esc → 설정에서 전체 음량을 바꿀 수 있다. 타이틀의 오디오 설정과 같은 값이 저장된다.

Fleet 데모의 이어하기와 불러오기에는 함선 저장 슬롯이 표시된다. 이전 개발 맵 저장 파일은 기존 폴더에 보존된다.

연출 대사와 미카의 채팅 답장은 하단 자막에, 현장 발언은 말풍선에 표시된다. L 대사 다시보기에는 전체 대사와 시스템 알림을 읽을 수 있는 탭이 있다. 기록을 열면 게임이 일시정지되며, 연출 중에 닫으면 같은 대사로 돌아온다.

빈 Enter와 Esc로 입력을 닫으면 이동으로 복귀한다. 전송한 문장은 비우며 미전송 초안은 Esc로 보존한다. 질문 입력과 F3 설정 중에도 전투는 계속된다. Esc 일시정지 메뉴는 월드·탄환·동료·지원·재사용 대기시간을 멈춘다.

ESC → 저장/불러오기 → 슬롯을 선택한다. 기존 슬롯은 같은 슬롯을 한 번 더 눌러 덮어쓴다. 전투 중 저장을 지원하고 사망·완료 상태의 저장은 제한한다. 불러오기는 진행 중 AI 요청·지원 행동·탄환·초안을 취소하고, 봉쇄 단계·각 무리의 적 체력/위치·일회용 보급·패널 확인 절차·기존 자원·서사·발견 지도·통합 기록·최근 AI 대화 기억을 복원한다. 패널의 미완료 동시 유지 시도는 취소되며, 1초 유지를 끝낸 비프 확인 절차는 이어진다. 저장 v3를 선택 필드로 확장했고 호환 v1/v2/v3 원본 파일은 읽기/변환 시 덮어쓰지 않는다. 저장 위치는 런처 기준 `runtime/appdata/Godot/app_userdata/로컬 AI NPC 연구 시제품/mission_saves/`다. 일시정지 메뉴에서 **타이틀로 돌아가기**를 누르기 전에 이어갈 진행은 슬롯에 저장한다.

정전 → 미카 호출 → 손전등 수령 → 비품실의 침식된 선원 3명 → 2인 패널 1초 유지/비프 → 퓨즈 획득 → 연구실 복귀 → 전력 복구 → 침식 경보 → 연구동 출발 문 E → 관측 단말 E → 봉쇄 보급함 E → 봉쇄 장치 E → 첫 무리 2명 → 두 번째 무리 3명 → 최종 봉쇄 패널 1초 동시 유지/비프 → 경보 해제/미카 마무리 대사 → **데모 완료**.

봉쇄는 연구동 외곽의 침식 확산을 일시적으로 차단하는 임무다. 내부 이상현상은 후속 조사 대상으로 남는다. 연구동 왼쪽 보급함은 양쪽 탄약·미카 예비탄·공용 치료/보급/보호 재고를 기존 최대치까지 한 번 보충한다. 전투 중 복귀문은 안전 격리로 잠기며, 전멸 후 왕복해도 적·보급·패널 진행이 재생성되지 않는다. 최종 패널은 한쪽에서 E를 유지하면 고정 공통 실행기로 미카가 반대편으로 이동한다. 대기 중이면 먼저 `따라와`, 다운이면 가까이 E로 소생한다. 무리 수는 `ContainmentMission.tscn`의 `first_wave_count`/`second_wave_count`(기본 2/3, 각각 1~6)로 조절한다.

정전된 비품실은 주변 시야와 마우스 방향 손전등을 사용하며, 전력 복구 뒤 밝아져도 가구 뒤는 가려진다. 초기 탄약이 제한되어 있으며, 미카의 보급 외에 비품실 남동쪽의 비상 탄약함을 한 번 사용할 수 있다.
미카는 동행하며 치료, 탄약 보급, 보호 장비 설치와 방향 안내를 실행한다. 보호 장비 반경 안에서는 기본적으로 피해가 절반이 된다. 터렛은 150px 이내에서 연사(발당 6), 그 밖의 330px 이내에서 레일건(발당 30)을 사용한다. 미카는 체력 100, 장전 탄약 20발, 예비탄 40발, 1.6초 자동 장전, 1초 사격 간격, 한 발 피해 25를 사용한다. 지원 접근 중에는 사격하지 않는다. 침식된 선원은 가구를 우회하고, 빠루를 내리치는 프레임에 가까운 캐릭터에게 피해를 준다. 탄환은 가구에 막힌다. 미카 다운은 가까이 E와 키트 1개로 소생하며 키트가 없거나 전투 자원을 모두 소진하면 기존 실패·재시작 흐름으로 전환한다. 플레이어 탄창/R 재장전과 무기 선택은 아직 없다.
치료 키트 2개, 보급품 2개, 보호 장비 1개를 세 방식에 동일하게 제공한다. 방을 왕복해도 사용한 자원이 재생되지는 않는다.

질문 입력 중에는 플레이어 이동만 멈춘다. **적과 전투는 계속된다.** 질문 전송 후에는 즉시 이동할 수 있다.
한글 입력창은 TextEdit 기반이다. 입력 중 본문·커서·선택 범위를 재설정하지 않고, 전송 전에 조합 글자를 확정한다. 300자를 넘는 내용은 전송을 막고 입력을 그대로 유지한다.
2026-10-26부터 Windows에서는 전용 확정 입력 연결 모듈을 함께 사용한다. DLL은 game/native/windows_ime에 포함되며 일반 실행에 별도 컴파일러가 필요하지 않다. 변경 후에는 게임을 완전히 닫고 다시 실행해야 한다. 상세 내용은 review/CHAT_INPUT_NATIVE_FIX_20261026.md와 native/windows_ime/README.md 참조.
추론 대기 중에도 게임 상태를 바꿀 수 있다. 맵 전환·사망·재시작 전의 답변은 폐기하며, 지원 판단은 응답 시점에 유효한지 다시 검사한다.

## 세 방식의 차이

| 방식 | 지원 행동 | 질문 답변 |
|---|---|---|
| RuleBased | 체력·탄약·전투 상태에 따른 고정 우선순위 | 키워드 의도 분류 + 준비된 문장 |
| LocalLLM | 같은 관측 정보와 유효 후보에서 구조화된 행동 선택 | 현재 임무·동료 관계·짧은 회차 기억을 바탕으로 자유 대사 생성 |
| Jev | 공식 Choice API로 같은 후보에서 선택 | 질문 의도 선택 + 준비된 문장 |

Jev 자체를 자유 대화 생성 모델로 간주하지 않는다. Jev에 LLM을 추가하는 경우는 별도 혼합 방식이다.
현재 Jev 어댑터·스키마·키 누락 처리는 구현했으나, **실제 API 인증/추론은 0회**다. 한 프로세스 실행의 Jev 호출 상한은 기본 60회다.
키 누락·인증 오류·호출 제한 등에서는 자동으로 다른 제공자로 바꾸지 않고 오류를 표시·기록한다.

행동 실행은 모두 `world.gd`의 같은 경로를 사용한다. 미카의 기본 이동, 치료량, 탄약량, 접근 거리, 장비 지속 시간, 자원 소비는 제공자에 따라 달라지지 않는다.
대화에서 “치료했어”라고 말하는 것만으로 체력이 바뀌지 않는다. 실제 효과는 유효한 지원 행동이 완료되어야 발생한다.

## 검증과 증거
